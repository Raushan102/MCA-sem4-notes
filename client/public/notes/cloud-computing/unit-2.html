Topic 1. Cloud Characteristics

YELLOWYELLOW priority: moderate detail, important fundamentals

NOTE

The five essential characteristics were studied in Unit I, Topic 7. They are revised here and connected to the cloud models of Unit II.

1.1 Meaning

Cloud characteristics are the features that explain how cloud computing services operate and how they provide computing resources to users. According to NIST (National Institute of Standards and Technology), cloud computing has five essential characteristics.

Figure: Five essential characteristics of cloud computing (NIST)

1.2 Five essential characteristics

1. On-demand self-service

Users obtain resources such as servers, storage and network capacity whenever required, without contacting the provider’s staff.
Example: creating a virtual machine through the AWS console.

2. Broad network access

Cloud services are available over a network and accessed through different devices using standard network mechanisms.
Example: Google Drive from a mobile phone, laptop or tablet.

3. Resource pooling

The provider combines computing resources into a shared pool and provides them to multiple customers according to their requirements.
Example: one provider serves many companies on its physical servers, keeping their data and environments logically separated.

4. Rapid elasticity

Resources can be quickly increased or decreased according to changing demand.
Example: an e-commerce website adds server capacity during a festival sale and reduces it afterwards.

5. Measured service

Resource usage is monitored, measured and reported, so providers and customers can track consumption and calculate charges.
Example: a customer is charged for the cloud storage or computing resources actually consumed.

1.3 Additional characteristics

CharacteristicMeaning
VirtualizationCreates virtual resources from physical hardware
Multi-tenancyMultiple customers share infrastructure with logical separation
AutomationPerforms resource management tasks automatically
ScalabilityAllows resources to grow according to requirements
ReliabilityHelps provide consistent services
SecurityProtects cloud resources and data

EXAM TIP

If the question asks for the five essential characteristics, write the five NIST characteristics. Treat the additional points separately.

1.4 Why are these characteristics important?

  • On-demand self-service provides resources quickly.
  • Broad network access makes services accessible.
  • Resource pooling improves resource utilization.
  • Rapid elasticity handles changing workloads.
  • Measured service gives usage transparency and supports billing.

These characteristics make cloud computing flexible, accessible, scalable and efficient.

Topic 4. Security in a Public Cloud

YELLOWYELLOW priority: related topic, moderate preparation

WHY STUDY THIS?

4.1 What is Public Cloud Security?

Definition: Public Cloud Security refers to the policies, technologies and security measures used to protect data, applications, networks and infrastructure hosted in a public cloud.

When an organization stores data or runs applications on a public cloud such as AWS, Microsoft Azure or Google Cloud, it must protect them from unauthorized access, data theft and cyberattacks.

Example: an online shop stores customer details, passwords and payment-related information on AWS. It must ensure:

  • Only authorized employees can access customer information.
  • Hackers cannot steal sensitive data.
  • Data stays protected while being transferred.
  • Applications remain available to customers.

4.2 Main security goals: CIA Triad

Figure: CIA Triad: the three main security goals

GoalMeaningExample
ConfidentialityOnly authorized people can access informationCustomer data visible only to authorized employees
IntegrityData must not be changed without permissionNobody can secretly modify transaction records
AvailabilityServices and data accessible when neededAn online shop stays available to customers

Remember: Confidentiality = Privacy, Integrity = Accuracy, Availability = Accessibility.

4.3 Major security concerns in a public cloud

Figure: Major security concerns in a public cloud

1. Data breach

Unauthorized people gain access to confidential information.
Example: a hacker accesses a cloud database and steals customer details.
Protection: encryption, strong passwords, access controls.

2. Data loss

Information is accidentally deleted, corrupted or becomes unavailable.
Example: an employee accidentally deletes important files in cloud storage.
Protection: regular backups, versioning, disaster recovery.

3. Unauthorized access

Someone accesses cloud resources without proper permission.
Example: an attacker uses a stolen employee password to enter a company’s cloud account.
Protection: multi-factor authentication (MFA), strong passwords, role-based access control.

4. Insecure APIs

An API (Application Programming Interface) lets different software communicate. Cloud services use APIs to manage resources and exchange data, so poorly secured APIs can be exploited.
Protection: API authentication, authorization, encryption and proper validation.

5. Account hijacking

Attackers take control of a legitimate user’s cloud account.
Example: an attacker steals login credentials and uses them on a company’s cloud dashboard.
Protection: MFA, secure login practices, suspicious-login monitoring.

6. Insider threats

A threat from someone who already has legitimate access, such as an employee or administrator.
Example: an employee intentionally downloads confidential information and shares it with outsiders.
Protection: limited permissions, activity monitoring, audit logs.

7. Privacy and compliance issues

Organizations may have to follow laws and regulations about personal and sensitive information.
Example: customer data stored in a location that does not meet applicable data protection requirements.
Protection: follow relevant regulations, know where data is stored, review the provider’s compliance arrangements.

4.4 Security measures used in a public cloud

Figure: Security measures used in a public cloud

Security measureWhat it does
EncryptionConverts readable data into an unreadable form without the required key

Important difference: Authentication = Who are you? Authorization = What are you allowed to access? Logging in with a username and password is authentication. Being allowed to view a file but not delete it is authorization.

Figure: Authentication vs authorization

4.5 Shared Responsibility Model

REDImportant concept

Security responsibilities are divided between the Cloud Service Provider (CSP) and the Cloud Customer. The provider protects the underlying cloud infrastructure, while the customer protects the resources and configurations they control.

Figure: Shared Responsibility Model

Responsibilities of the cloud provider

  • Physical data centre security.
  • Physical servers and hardware.
  • Physical networking infrastructure.
  • Underlying virtualization infrastructure.
  • Maintaining the cloud infrastructure.

Responsibilities of the cloud customer

  • Protecting their data.
  • Managing user accounts and permissions.
  • Configuring access controls.
  • Securing applications.
  • Protecting customer-controlled systems and configurations.

The exact division changes with IaaS, PaaS or SaaS. An IaaS customer manages the operating system, whereas a SaaS provider manages much more of the software stack.

4.6 Advantages of public cloud security

  • Centralized security: controls managed through a central cloud platform.
  • Scalability: security resources adjust as workloads grow.
  • Monitoring: cloud activity can be monitored continuously.
  • Backup and recovery: supports data backup and recovery.
  • Security tools: providers offer tools for encryption, access control and threat detection.

However, a reputed provider does not automatically make your cloud environment secure. Incorrect configurations and weak access controls can still create serious risks.

Topic 5. Public Versus Private Clouds

REDRED priority: previous-year question found

PREVIOUS-YEAR QUESTION (15 MARKS)

Q. Differentiate between Public Cloud and Private Cloud.

Ranchi University MCA Semester IV, ECMCA-401C, 2022–24 paper collection.

5.1 Public Cloud

Definition: A Public Cloud is a cloud environment in which computing resources are provided by a third-party cloud service provider over the internet and made available to multiple customers.
Example: a company uses Amazon Web Services (AWS) to host its website instead of buying its own physical servers.

Main characteristics:

  • Infrastructure is owned and managed by a cloud service provider.
  • Resources are shared among multiple customers.
  • Services are accessed through the internet.
  • Usually needs less initial investment.
  • Resources can be scaled according to demand.
  • Customers have limited control over the physical infrastructure.

Examples: AWS, Microsoft Azure, Google Cloud.

5.2 Private Cloud

Definition: A Private Cloud is a cloud environment dedicated to a single organization. Its infrastructure may be managed by the organization itself or by a third-party provider.
Example: a bank maintains a dedicated cloud environment for confidential customer records and financial information.

Main characteristics:

  • Infrastructure is dedicated to one organization.
  • Greater control over resources.
  • Security policies can be customized.
  • Higher initial investment in many deployments.
  • Greater control over infrastructure configuration.
  • Suitable for strict security and compliance requirements.

Figure: Public cloud (shared) vs private cloud (dedicated)

5.3 Difference between Public Cloud and Private Cloud

This comparison table is the most important part of your exam answer.

BasisPublic CloudPrivate Cloud
DefinitionCloud services provided to multiple customersCloud infrastructure dedicated to one organization

InfrastructureShared, with logical separation between customersDedicated to a single organization

5.4 Advantages and disadvantages

Public Cloud

Advantages

  1. Low initial investment.
  2. Easy scalability.
  3. No need to buy physical servers.
  4. The provider handles physical infrastructure maintenance.
  5. Resources can be accessed from different locations.

Disadvantages

  1. Less direct control over physical infrastructure.
  2. Dependence on the service provider.
  3. Security and privacy need careful configuration.
  4. Internet connectivity may affect access.

Private Cloud

Advantages

  1. Greater control over infrastructure.
  2. Customizable security policies.
  3. Dedicated resources for one organization.
  4. Greater flexibility in configuration.
  5. Useful for specific compliance requirements.

Disadvantages

  1. Higher setup costs in many cases.
  2. Maintenance can be expensive.
  3. Needs skilled IT professionals.
  4. Scaling may need additional investment.

5.5 Conclusion

Public Cloud and Private Cloud are two important cloud deployment models. Public Cloud provides shared services with lower initial investment and easy scalability, whereas Private Cloud provides dedicated infrastructure with greater organizational control and customization. An organization selects the model according to its budget, security requirements, control needs and business objectives.

6.1 What is Cloud Infrastructure Self-Service?

Definition: a feature that lets users access, request, configure and manage cloud computing resources themselves through a web portal or dashboard, without direct help from the cloud provider.

Example: you need a virtual machine for a Python application. Instead of contacting the provider and waiting for an employee to create a server:

  1. Log in to AWS.
  2. Select a virtual machine service.
  3. Choose the required configuration.
  4. Launch the virtual machine.
  5. Start using it.

  2. User control: select resource configurations.
  3. Automated provisioning: resources can be created automatically.

  5. Access control: permissions decide which resources users can manage.

7.1 What does Gamut of Cloud Solutions mean?

The word gamut means a complete range or variety. Gamut of Cloud Solutions is the wide range of services and solutions that cloud computing offers to individuals and organizations. Instead of buying and managing all IT resources, organizations use cloud solutions according to their requirements.

7.2 Main types of cloud solutions

Figure: Gamut of cloud solutions

1. Infrastructure as a Service (IaaS)

Computing infrastructure such as virtual machines, servers, storage and networking. Example: Amazon EC2.

2. Platform as a Service (PaaS)

A platform to develop, test and deploy applications. Example: Google App Engine.

3. Software as a Service (SaaS)

Ready-to-use software through the internet. Example: Gmail, Google Docs.

4. Storage as a Service (STaaS)

Online storage space to store and retrieve data. Example: Google Cloud Storage, Amazon S3.

5. Desktop as a Service (DaaS)

A virtual desktop environment through the cloud, accessed remotely from supported devices. Example: Amazon WorkSpaces.

8.1 What are principal technologies?

The main technologies that make cloud computing possible. Cloud providers combine several technologies to deliver servers, storage, databases and applications over the internet.
Example: when you upload a photo to Google Drive, many technologies work together behind the scenes to store it and make it available on different devices.

8.2 Major technologies used in cloud computing

Figure: Principal technologies behind cloud computing

These are important supporting technologies, an explanatory list and not a verbatim syllabus list.

  1. Virtualization: one physical server runs multiple virtual machines. Example: separate virtual servers for different customers.
  2. Distributed computing: divides work among multiple computers connected through a network. Example: many machines process large amounts of data.
  3. Web services and APIs: let software applications communicate over a network. Example: an application uses a provider’s API to create a virtual machine.
  4. Service-Oriented Architecture (SOA): organizes software into independent, reusable services. Example: separate payment, user-management and delivery services.
  5. Networking and internet technologies: high-speed networks connect users to cloud data centres.
  6. Data centre technology: physical servers, storage, networking equipment, power and cooling systems.
  7. Multi-tenancy and resource pooling: many customers share physical infrastructure with logical separation.
  8. Automation and orchestration: automation performs tasks automatically, orchestration coordinates multiple automated tasks. Example: a platform creates a VM when a customer requests one.
  9. Storage technologies: store and manage files, databases and backups. Example: cloud object storage for photos and videos.
  10. Security technologies: authentication, authorization, encryption, firewalls and monitoring.

Topic 9. Cloud Strategy

9.1 What is a Cloud Strategy?

A Cloud Strategy is a plan made by an organisation to decide how it will use cloud computing to achieve its business and IT goals. Before moving applications, data or servers to the cloud, it decides:

  • Why does it need cloud computing?
  • Which applications should move to the cloud?
  • Which cloud model should it choose?
  • How much will it cost?
  • How will it protect its data?
  • How will it manage and monitor cloud services?

Example: a college wants to move its student-management system to the cloud. It plans the budget, selects a provider, decides how to migrate student data and sets security rules. This planning is its cloud strategy.

9.2 Main components of a cloud strategy

Figure: Main components of a cloud strategy

  1. Business goals: what the organisation wants to achieve (lower IT cost, better performance, growth).
  2. Cloud model selection: Public, Private, Hybrid or Community Cloud.
  3. Cloud service selection: IaaS, PaaS or SaaS.
  4. Cost planning: estimate storage, computing, networking and support expenses.
  5. Security and compliance: protect data, control access, meet legal or regulatory requirements.
  6. Migration planning: how existing applications, databases and files move to the cloud.
  7. Monitoring and management: performance, availability, resource usage and costs.

9.3 Basic steps for developing a cloud strategy

Figure: Steps for developing a cloud strategy

  1. Identify requirements: understand business and IT needs.
  2. Assess existing infrastructure: check servers, applications, databases and networks.
  3. Select cloud models and services: choose suitable deployment and service models.
  4. Plan security and budget: set security policies and estimate costs.
  5. Prepare a migration roadmap: decide what to move, when and how.
  6. Monitor and optimise: check performance, security and expenses after adoption.

9.4 Why is cloud strategy important?

  • Helps achieve business goals.
  • Controls unnecessary cloud expenses.
  • Improves security and risk management.
  • Helps select suitable cloud services.
  • Makes migration more organised.
  • Supports future business growth.

9.5 Cloud Strategy vs Cloud Migration

Topic 10. Cloud Design and Implementation Using SOA

REDRED priority: 15-mark question, study thoroughly

PREVIOUS-YEAR QUESTION STATUS

Marked RED for exam preparation. The compiled collection includes this 15-mark question: Explain Cloud Design and Implementation using SOA. It is a related question, not confirmed as a direct question from the primary 2022–24 MCA Semester IV paper. Listed under Unit II-B: Cloud as a Service.

10.1 Introduction to SOA

SOA stands for Service-Oriented Architecture. It is a software architectural approach in which an application is divided into independent, reusable services. Each service performs a specific business function and communicates with other services through well-defined interfaces, commonly APIs.

An online shopping application can have:

  • Authentication Service: login and registration.
  • Payment Service: processes payments.
  • Product Service: manages products.
  • Order Service: manages orders.
  • Notification Service: sends notifications.

10.2 SOA architecture diagram

Figure: SOA architecture: consumers, ESB, provider services and databases (bookstore example)

10.3 What is Cloud Design and Implementation Using SOA?

Designing an application using SOA principles and deploying its services on cloud infrastructure. Two separate concepts:

  • SOA: defines how an application is divided into independent services and how they communicate.
  • Cloud Computing: provides virtual machines, storage, databases and networks to run those services.

Example: an organisation develops Authentication, Payment and Order services and deploys them on cloud servers instead of buying and maintaining physical servers.

10.4 Components of SOA

  1. Service: an independent software component that performs a particular task.
  2. Service Provider: creates and provides services to other applications.
  3. Service Consumer: requests and uses services from the provider.
  4. Service Registry: stores service information so consumers can discover available services.

10.5 Publish, Find, Bind model

Figure: Publish, Find, Bind model of SOA

  1. Publish: the service provider publishes information about its service.
  2. Find: the service consumer searches for the required service.
  3. Bind: the consumer connects to and uses the service.

10.6 Principles of SOA

Figure: Principles of SOA

  • Loose coupling: services have minimum dependency on each other.
  • Reusability: a service can be reused by multiple applications.
  • Interoperability: services built with different technologies can communicate.
  • Service abstraction: internal implementation details are hidden.
  • Autonomy: each service controls its own functionality.
  • Discoverability: services can be discovered using descriptions or registries.

10.7 Steps in cloud design and implementation using SOA

  1. Identify requirements: understand the business requirements of the application.
  2. Identify services: divide the application into independent services.
  3. Define interfaces: specify how services communicate and exchange information.
  4. Develop services: develop or integrate the required services.
  5. Deploy on cloud: deploy services using cloud infrastructure.
  6. Enable communication: connect services using APIs and communication protocols.
  7. Apply security: implement authentication, authorization and encryption.
  8. Monitor services: monitor performance, availability and resource usage.

10.8 Benefits of SOA in cloud computing

  1. Reusability: services can be reused by different applications.
  2. Scalability: individual services can be scaled according to demand.
  3. Flexibility: services can be modified independently.
  4. Cost reduction: existing services are reused instead of rebuilt.
  5. Interoperability: different technologies can communicate.
  6. Easy maintenance: independent services are easier to maintain.

10.9 Example

An online shopping application on cloud infrastructure. When a customer buys a product:

  1. Authentication Service verifies the customer.
  2. Product Service provides product details.
  3. Order Service creates the order.
  4. Payment Service processes the payment.
  5. Notification Service sends confirmation.

All services communicate through APIs and run using cloud resources.

10.10 Conclusion

SOA helps developers design applications using independent, reusable services, while cloud computing provides the infrastructure to deploy and run them. Together they help organisations build flexible, scalable and manageable cloud-based applications.

Topic 11. Conceptual Cloud Model

BLACKBLACK priority: one-time reading

PREVIOUS-YEAR QUESTION CHECK

11.1 What is a Conceptual Cloud Model?

A high-level representation of how cloud computing works, showing its major components, participants, services and their relationships. It explains:

  • Who provides cloud services?
  • Who uses them?
  • How are they delivered?
  • What are the service layers?
  • Who manages security and auditing?

It explains the overall structure without focusing on a particular company’s technology. The NIST Cloud Computing Reference Architecture is a recognised example.

11.2 The five actors

Figure: Conceptual Cloud Model: five NIST actors

1. Cloud Consumer

A person or organisation that uses cloud services. Example: a company using AWS virtual machines, or a student using Google Drive.

2. Cloud Provider

An organisation that provides cloud services to consumers (AWS, Microsoft Azure, Google Cloud). It manages the infrastructure and delivers IaaS, PaaS and SaaS.

3. Cloud Broker

An intermediary between consumers and providers. It helps select, combine or manage services from different providers. Three functions:

  • Service intermediation: adds value to an existing service, such as identity management.
  • Service aggregation: combines multiple cloud services into one solution.
  • Service arbitrage: selects services dynamically from different providers based on requirements.

4. Cloud Auditor

Independently examines cloud services and operations: security, privacy, performance and compliance. Example: an auditor checks whether a provider follows the required security standards.

5. Cloud Carrier

Provides the network connection through which services travel from provider to consumer. Example: an internet service provider.

11.3 Internal layers of the cloud provider

Figure: Internal layers of the cloud provider

  • A. Service layer: IaaS, PaaS and SaaS.
  • B. Resource abstraction and control layer: manages and controls underlying resources using virtualisation and resource allocation.
  • C. Physical resource layer: servers, storage devices, network equipment and data centre facilities.
  • D. Cloud service management: business support, provisioning and configuration, portability and interoperability.

Security and privacy are cross-cutting concerns across the provider’s architecture.

11.4 How does the model work?

A company wants cloud storage:

  1. The company is the Cloud Consumer.
  2. It selects a cloud provider.
  3. The Cloud Provider offers storage services.
  4. The Cloud Carrier provides internet connectivity.
  5. A Cloud Broker may help compare or manage services.
  6. A Cloud Auditor may independently check security and compliance.
  7. The provider manages its physical resources, service delivery and security.

11.5 Importance

  1. Better understanding: explains the overall structure of cloud computing.
  2. Role identification: identifies the responsibilities of different actors.
  3. Service understanding: shows how IaaS, PaaS and SaaS fit into the provider architecture.
  4. Security awareness: shows the importance of security and privacy.
  5. Service management: shows how services are delivered and managed.
  6. Standardisation: a common reference for discussing and comparing cloud architectures.

12.1 What is a cloud service?

A computing resource or application made available to users over a network, usually the internet, by a cloud service provider. Instead of buying and maintaining all computing infrastructure, users access services from companies such as AWS, Microsoft Azure and Google Cloud.

Examples: online storage (Google Drive), cloud servers (AWS EC2), application platforms (Google App Engine), online software (Microsoft 365).

The three major service models: IaaS, PaaS, SaaS.

Figure: IaaS, PaaS and SaaS with examples

12.2 Understanding the three models

To build and run a website there are three ways to use cloud services:

  • IaaS: the provider gives virtual servers, storage and networking. You manage the operating system, runtime, application and data.
  • PaaS: the provider gives a platform to develop and run applications. You mainly focus on your code and data.
  • SaaS: the provider gives ready-to-use software. You simply use the application.

12.3 IaaS: Infrastructure as a Service

Definition: a cloud service model in which a provider offers fundamental computing resources such as virtual machines, storage and networking over the internet. The provider manages the physical infrastructure; the customer manages the operating system, applications and data.

What IaaS provides:

  1. Virtual machines (install your own operating system).
  2. Storage for files and databases.
  3. Networking: virtual networks, IP addresses, connectivity.
  4. Load balancers: distribute incoming traffic across servers.
  5. Firewalls: help control network access.

Example: AWS EC2. To host a website: create a virtual machine, select an operating system such as Ubuntu, install Python and libraries, deploy your application, configure networking and security. The provider manages the physical server; you manage the operating system and application.

Advantages: no physical servers to buy; resources increase or decrease as required; control over the operating system; pay for what you use; suitable for websites and custom applications.
Examples: AWS EC2, Microsoft Azure Virtual Machines, Google Compute Engine.

12.4 PaaS: Platform as a Service

Definition: a cloud service model that provides a ready-made environment for developers to build, test, deploy and manage applications without managing the underlying infrastructure. The provider manages servers, operating system, runtime and development environment.

What PaaS provides: operating system management, language runtimes, development tools, web servers, database integration, deployment tools, infrastructure management.

Example: Google App Engine. For a FastAPI web application, without PaaS you would create a server, install Ubuntu and Python, configure the web server, install dependencies, deploy and maintain it. With PaaS the provider handles most of this; you mainly provide your code and configure deployment.

Advantages: developers focus on code; less infrastructure management; faster development; deployment and development tools; supports scaling; easier collaboration.
Examples: Google App Engine, Heroku, Azure App Service.

12.5 SaaS: Software as a Service

Definition: a cloud service model in which a provider delivers ready-to-use software applications over the internet. Users access it through a browser or application. The provider manages the infrastructure, platform, application maintenance and updates.

What SaaS provides: ready-to-use software, online access, software updates, application maintenance, data storage and management, user management features.

Example: Gmail. Open Gmail, sign in, compose an email, send it. You do not install or manage the email server, operating system or infrastructure; Google manages the service.

Advantages: no software infrastructure to install or maintain; accessible from different devices; automatic updates; easy collaboration; subscription or usage-based access; less local IT maintenance.
Examples: Gmail, Microsoft 365, Salesforce, Google Workspace, Dropbox.

How can a third party manage SaaS? A third-party SaaS management provider or Managed Service Provider (MSP) helps an organisation manage its SaaS applications.

Figure: What a third-party provider (MSP) does for SaaS

  1. User management: create, update and deactivate user accounts.
  2. Access control: assign permissions and control who can access applications.
  3. Security management: monitor security settings and help protect accounts.
  4. Integration: connect different SaaS applications with each other.
  5. Monitoring: monitor application availability and performance.
  6. Backup and recovery: help manage backup and recovery arrangements where supported.
  7. Cost management: monitor subscriptions, licences and unnecessary expenses.
  8. Compliance: help follow security and regulatory requirements.

Example: a company uses Microsoft 365. It hires a third-party IT management company to manage employee accounts, permissions, security settings, licences and support. The third party manages the organisation’s use of SaaS; Microsoft still operates and maintains the service itself.
