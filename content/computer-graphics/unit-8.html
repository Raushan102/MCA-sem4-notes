1.1 Meaning of a Function of Two Variables

A function of two variables takes two independent input values, usually x and y, and produces one output value, usually z. In computer graphics, this form is useful for describing a 3D surface over the x-y plane.

Explicit surface representation

z = f(x, y)

For every pair (x, y), the function gives the corresponding height or depth value z.

1.2 Example of a Surface Function

Consider the function:

z = 2x + 3y

If x = 1 and y = 2, then:

z = 2(1) + 3(2) = 8

Therefore, the point on the surface is (1, 2, 8). By calculating z for many pairs of x and y, we can obtain points that form a 3D surface.

1.3 Common Ways to Represent a Surface

  • Explicit form: The dependent coordinate is written directly as a function of two independent coordinates, for example z = f(x, y).
  • Implicit form: The surface is described by an equation involving x, y and z, for example F(x, y, z) = 0.

Example of an implicit surface:

x² + y² + z² − 25 = 0

This equation represents a sphere of radius 5 centred at the origin.

1.4 Domain and Range

  • Domain: The set of allowed input pairs (x, y) for which the function is defined.
  • Range: The set of output values z produced by the function.

For example, if z = x + y and both x and y are restricted to values from 0 to 2, the domain is the selected square region in the x-y plane, and the output z ranges from 0 to 4.

1.5 Connection with Visible-Surface Determination

When a 3D scene is projected onto a 2D viewing plane, different surfaces may overlap at the same screen position. A surface function can provide the z value at a particular (x, y) position. This value helps determine the relative depth of the surface at that position.

  • For a given projected position (x, y), calculate or obtain the depth of each surface covering that position.
  • Compare the depth values using the viewing system's depth convention.
  • The surface nearest to the viewer is the visible one at that position; the other surface is hidden there.

Important: Whether the nearest surface has the smaller or larger numerical z value depends on the coordinate and depth convention being used. Do not assume that the smallest z is always closest in every system.

1.6 Why This Concept Is Useful

  • It provides a mathematical way to describe 3D surfaces.
  • It helps calculate the depth of a surface at a given projected position.
  • It provides a foundation for understanding depth comparison in visible-surface algorithms.

Exam Answer

A function of two variables is a mathematical function in which two independent variables, usually x and y, determine a third value z. In computer graphics, a 3D surface can be represented in explicit form as z = f(x, y), where each pair (x, y) gives a point on the surface. A surface may also be represented implicitly by an equation such as F(x, y, z) = 0. These functions are useful in visible-surface determination because they can provide the depth value of a surface at a projected position. When multiple surfaces overlap at the same screen position, their depth values are compared according to the viewing coordinate convention to identify the surface nearest to the viewer.

2Topic 2 of 7Efficient Visible-Surface AlgorithmsYELLOW PRIORITY

Why YELLOW? The available exam-plan evidence records older MCA questions on Z-buffer and depth-sort, which are examples of visible-surface techniques. 2.1 Meaning and Need

Visible-surface determination (also called hidden-surface removal) identifies the surfaces or parts of objects that can be seen from a given viewing position. Surfaces hidden behind nearer opaque surfaces are not displayed.

In a complex 3D scene, checking every surface repeatedly can take considerable processing time. Efficient algorithms reduce unnecessary calculations and avoid drawing hidden parts wherever possible.

2.2 Main Approaches

  • Object-space methods: Compare objects or surfaces with one another in the 3D scene to decide which parts are visible. These methods work with the geometric objects themselves.
  • Image-space methods: Decide visibility at positions on the projected image, usually pixel by pixel. The algorithm determines which surface is nearest at each image position.
  • Mixed methods: Combine object-space and image-space operations, for example by arranging surfaces using depth and then resolving visibility in the image.
Remember: Object-space methods reason about the scene geometry; image-space methods reason about the projected image pixels.

2.3 Sorting

Sorting means arranging surfaces according to their depth or distance from the viewer. It helps the algorithm compare overlapping surfaces in a useful order.

For example, in a painter-style approach, farther surfaces are drawn first and nearer surfaces are drawn later, so nearer surfaces cover the farther ones. Depth sorting is useful, but intersecting or cyclically overlapping polygons may require additional tests or splitting.

2.4 Coherence

Coherence is the tendency for nearby parts of a scene or image to have similar properties. Efficient algorithms use already calculated information when it is likely to remain valid for nearby positions, instead of repeating the same work.

  • Object coherence: Parts belonging to the same object often share useful properties.
  • Face coherence: Nearby points on one face generally belong to that same face.
  • Edge coherence: The visibility relationship along a polygon edge usually changes gradually.
  • Scan-line coherence: Adjacent scan lines often have similar visibility patterns.
  • Area coherence: Nearby pixels in a small screen region are often covered by the same surface.
  • Depth coherence: Depth values at nearby points on a surface usually change smoothly.
  • Frame coherence: Consecutive animation frames usually differ only where objects or the viewpoint have changed.

2.5 Examples of Techniques

  • Back-face detection: Removes polygon faces that point away from the viewer, avoiding further visibility work for those faces.
  • Z-buffer method: Stores depth for each pixel and keeps the nearest surface found at that pixel.
  • Scan-line method: Processes the image one horizontal scan line at a time and uses similarities between spans and adjacent lines.
  • Depth-sort / painter’s method: Orders surfaces by depth before drawing them.
  • Area-subdivision method: Divides the viewing area into smaller regions until visibility in each region can be determined.

These techniques exploit different combinations of object-space processing, image-space processing, sorting and coherence. The later topics in this unit explain several of them separately.

2.6 Choosing an Efficient Method

The suitable method depends on factors such as:

  • Number and complexity of objects in the scene.
  • Whether the objects are polygons or other surface types.
  • Available memory and processing capability.
  • Whether the scene is static or animated.
  • Required image quality and handling of overlapping or transparent surfaces.

2.7 Exam-Oriented Answer

Efficient visible-surface algorithms determine which parts of a 3D scene are visible from a specified viewpoint while reducing unnecessary calculations. They are commonly classified into object-space, image-space and mixed methods. Their efficiency is improved using sorting, which orders surfaces according to depth, and coherence, which reuses information about nearby objects, faces, edges, scan lines, areas, depths or frames. Examples include back-face detection, Z-buffer, scan-line, depth-sort and area-subdivision methods.

3Topic 3 of 7Scan-Line DeterminationBLACK PRIORITY

Why BLACK? The available exam-plan evidence does not confirm a separate direct MCA question specifically on the Scan-Line Determination algorithm. The topic is part of the official Unit VIII syllabus and is a standard visible-surface detection method.

3.1 Meaning

The scan-line method is an image-space visible-surface detection method. It determines the visible surface one horizontal scan line at a time, moving across the screen from left to right and then proceeding to the next scan line.

Instead of keeping depth information for the entire image, the method needs depth information for the current scan line. All polygons intersecting that scan line are considered together.

3.2 Data Structures Used

  • Edge Table (ET): Stores polygon edge information, such as edge endpoints, the inverse slope and a reference to the polygon to which the edge belongs. It helps identify where edges intersect scan lines.
  • Polygon Table (PT): Stores polygon information, such as plane coefficients, surface properties and references to related edges.
  • Active Edge List (AEL): Contains only the edges that intersect the current scan line. The edges are maintained in increasing order of their x-coordinate.
  • Inside/outside flag: Each polygon has a flag indicating whether the current position along the scan line lies inside or outside that polygon.

3.3 Working of the Scan-Line Method

  1. Start with the first scan line at the top of the viewing area.
  2. Use the Edge Table to find all polygon edges intersecting the current scan line.
  3. Build the Active Edge List and arrange its edges in increasing x-coordinate order.
  4. Move from left to right across the scan line. When a polygon's left boundary is reached, turn its inside flag ON.
  5. When its right boundary is reached, turn its inside flag OFF.
  6. If no polygon is active, the position belongs to the background. If exactly one polygon is active, that polygon is visible there.
  7. If two or more polygons overlap at a position, compare their depth values and select the nearest surface according to the viewing convention.
  8. Store the selected surface's intensity or colour in the frame buffer for the corresponding pixels.
  9. Update the active edges for the next scan line and repeat until the entire viewing area has been processed.

3.4 Why Depth Comparison Is Needed

When only one polygon covers a part of the scan line, its surface is visible without comparing it against another polygon. When multiple polygons cover the same position, the algorithm calculates or updates their depth values and chooses the nearest one.

Important: The numerical meaning of “nearer” depends on the chosen depth-coordinate convention. The algorithm compares depths consistently using that convention.

3.5 Scan-Line Coherence

Scan-line coherence means that neighbouring scan lines often have similar edge intersections and visibility relationships. The algorithm can use information from the previous scan line to update the active edge list instead of rebuilding everything from the beginning.

This reduces repeated work when adjacent scan lines pass through the same polygons.

3.6 Advantages and Limitations

  • Advantages: Processes only one scan line of depth information at a time; considers all polygons crossing that line together; can exploit scan-line coherence to reduce repeated calculations.
  • Limitations: Requires management of edge and polygon tables; overlapping polygons require depth comparisons; the active edge list must be updated as each scan line is processed.

3.7 Exam-Oriented Answer

The scan-line method is an image-space algorithm for visible-surface determination. It processes the image one horizontal scan line at a time. It uses an Edge Table, Polygon Table and an Active Edge List. The active edges are sorted by increasing x-coordinate. As the algorithm moves from left to right, a polygon's inside flag is switched ON at its left boundary and OFF at its right boundary. If several polygons overlap, their depth values are compared and the nearest surface is written to the frame buffer. Scan-line coherence helps reuse information from neighbouring scan lines and reduces repeated work.

4Topic 4 of 7Z-Buffer AlgorithmsRED PRIORITY

Why RED? The available exam-plan evidence records a Z-buffer question in the older MCA paper (MCA-2/D-12, code CS-DE-21). The exact original wording is not preserved in the available notes, so this is topic-level PYQ evidence rather than a verbatim question.

4.1 Meaning of the Z-Buffer

The Z-buffer algorithm, also called the depth-buffer algorithm, is an image-space method used to determine which surface is visible at each pixel. It stores the depth of the currently visible surface for every pixel in a special memory area called the Z-buffer.

The frame buffer stores the pixel's colour or intensity, while the Z-buffer stores its depth value.

4.2 Buffers Used

  • Frame Buffer: Stores the colour or intensity value that will appear at each screen pixel.
  • Z-Buffer: Stores the depth value of the surface currently selected as visible at each pixel.

Both buffers have corresponding entries for the pixels in the image.

4.3 Working Principle

  1. Initialize every Z-buffer entry to a depth value representing the farthest possible depth (or the appropriate initial value for the chosen depth convention).
  2. Initialize the frame buffer with the background colour.
  3. Process each polygon or surface in the scene.
  4. For every pixel covered by the current surface, calculate or obtain its depth value.
  5. Compare this depth with the value already stored at that pixel in the Z-buffer.
  6. If the new surface is nearer, update the Z-buffer entry with the new depth and update the corresponding frame-buffer pixel with the surface colour.
  7. If the new surface is farther, leave both buffer entries unchanged.
  8. After all surfaces have been processed, the frame buffer contains the visible image.

Depth comparison (concept)

If new depth is nearer → update Z-buffer and frame buffer

Otherwise → keep the existing values

The comparison operator depends on the depth-coordinate convention. In one convention smaller depth means nearer; in another, larger depth may mean nearer.

4.4 Simple Example

Suppose two opaque surfaces cover the same pixel. Surface A has depth 8 and Surface B has depth 3. If smaller depth represents a nearer surface, Surface B is selected.

The Z-buffer stores depth 3, and the frame buffer stores the colour of Surface B at that pixel. If the depth convention is reversed, the comparison must also be reversed.

4.5 Advantages

  • Simple and widely used method for visible-surface detection.
  • Surfaces can generally be processed in any order because each pixel keeps the nearest depth found so far.
  • Suitable for scenes containing many overlapping polygons.
  • Visibility decisions are made independently for each pixel.

4.6 Limitations

  • Requires additional memory for the Z-buffer.
  • Depth precision is limited by the number of bits used to store each depth value.
  • Insufficient depth precision can cause Z-fighting, where nearly coplanar surfaces compete and the displayed result may flicker or appear irregular.
  • Basic Z-buffering handles opaque surfaces directly; transparency generally requires additional handling and correct blending order.

4.7 Exam-Oriented Answer

The Z-buffer or depth-buffer algorithm is an image-space visible-surface detection technique. It uses two buffers: the frame buffer, which stores pixel colours, and the Z-buffer, which stores pixel depths. Initially, the Z-buffer is filled with the farthest depth and the frame buffer with the background colour. Each polygon is processed, and its depth is compared with the stored depth at every covered pixel. If the new surface is nearer, both the Z-buffer and frame-buffer entries are updated. Otherwise, the old values are retained. After all polygons are processed, the frame buffer represents the visible scene.

5.1 Meaning

List-priority algorithms determine a visibility order for the surfaces in a scene. The surfaces are arranged in a list according to their depth priority, and then drawn in that order so that nearer surfaces cover farther surfaces.

The best-known example is the Painter’s Algorithm, also called the Depth-Sort Algorithm or Priority Algorithm.

5.2 Painter’s Algorithm — Basic Idea

The method works like an artist painting a picture. The artist first paints the background and distant objects, then paints nearer objects over them. In the same way, the algorithm draws polygons from back to front:

  • Farther polygons are drawn first.
  • Nearer polygons are drawn later.
  • When a nearer polygon covers a farther polygon, its pixels overwrite the earlier pixels in the frame buffer.

5.3 Working Steps

  1. Find the depth range of each polygon, commonly represented by its minimum and maximum depth values.
  2. Sort the polygons according to depth priority, arranging them from farthest to nearest.
  3. Initialize the frame buffer with the background colour.
  4. Scan-convert and draw the farthest polygon first.
  5. Continue drawing the remaining polygons in back-to-front order. Later, nearer polygons overwrite pixels belonging to farther polygons wherever they overlap.
  6. Check ambiguous overlapping polygons. If their depth order cannot be established safely, perform additional tests and split polygons when necessary.

5.4 Handling Overlapping Polygons

Sorting only by one depth value may not be sufficient when polygon depth ranges overlap. The algorithm uses additional tests to decide whether the assumed order is valid.

  • Screen extent test: Check whether the projected x- or y-ranges of two polygons are separate. If they do not overlap in either direction, one cannot cover the other in the image.
  • Depth-range test: Compare the minimum and maximum depth ranges. If one polygon is entirely behind the other, their order can be established.
  • Plane test: Check whether the polygons lie on opposite sides of the other polygon’s plane, where applicable.
  • Splitting: If no reliable order can be established, divide one or both polygons into smaller parts so that the pieces can be placed in a consistent back-to-front order.

5.5 Cyclic Overlap Problem

A difficult case occurs when polygons overlap in a cycle: polygon A appears in front of B in one region, B appears in front of C, and C appears in front of A. No single global drawing order can satisfy all these relationships.

In such cases, the algorithm may need to split polygons into smaller pieces. After splitting, the pieces can often be sorted and drawn in a valid order.

5.6 Advantages

  • The basic idea is simple and easy to understand.
  • It can be efficient when the polygons have a clear, consistent depth order.
  • It does not require a separate depth value to be stored for every screen pixel in the way a Z-buffer does.

5.7 Limitations

  • Sorting and checking overlapping polygons can be expensive.
  • Intersecting or cyclically overlapping polygons may not have a simple global order.
  • Polygon splitting may be required, increasing processing complexity.
  • Farther polygons may be drawn even in areas that are later covered by nearer polygons, causing unnecessary drawing work.

5.9 Exam-Oriented Answer

List-priority algorithms determine the visibility order of surfaces by arranging them in a list according to depth. The Painter’s Algorithm, also called the depth-sort or priority algorithm, is a common example. It draws polygons from farthest to nearest. The frame buffer is first filled with the background colour. Far polygons are drawn first, and nearer polygons are drawn later, overwriting the pixels of distant polygons wherever they overlap. If overlapping polygons cannot be placed in a correct order, additional overlap tests are performed and polygons may be split. The method is simple, but sorting, intersecting surfaces and cyclic overlap can make it expensive.

6.1 Meaning

The area-subdivision algorithm is an image-space visible-surface detection method. It divides the viewing screen into smaller areas and determines which surface is visible in each area. If visibility cannot be decided for an area, that area is subdivided again into smaller regions.

The process continues until the visible surface can be identified or the region becomes small enough to be treated as a pixel.

6.2 Basic Principle

The algorithm uses the idea that a region may be classified easily when the surfaces covering it have a simple relationship. It checks the polygons that overlap a region and decides whether one polygon is definitely visible throughout that region.

  • If a region is clearly covered by one visible surface, display that surface.
  • If the region contains no polygon, display the background.
  • If visibility is ambiguous because multiple surfaces overlap, divide the region into smaller parts and test each part again.

6.3 Working Steps

  1. Start with the entire viewing area as one region.
  2. Identify the polygons that overlap the current region.
  3. Test whether the region can be assigned to a single visible surface using coverage and depth information.
  4. If no polygon covers the region, fill it with the background colour.
  5. If one polygon is definitely visible throughout the region, fill the region with that polygon's colour or shading.
  6. If the visibility test is ambiguous, divide the region into four smaller subregions.
  7. Apply the same tests recursively to each subregion.
  8. Stop subdividing when visibility is resolved or the region reaches the chosen minimum size, commonly a pixel.

6.4 The Four Subregions

A common implementation divides a rectangular region into four equal quadrants:

Top-left · Top-right

Bottom-left · Bottom-right

Each quadrant is tested independently. Only ambiguous quadrants need further subdivision.

This repeated four-way division creates a hierarchical structure similar to a quadtree, where each parent region can have four child regions.

6.5 Tests for Determining Visibility

The algorithm examines the polygons overlapping a region. A region can be classified when the coverage and depth relationships show that a particular polygon is in front throughout that region. If the polygons overlap in a way that prevents a safe decision, subdivision is used to make the problem smaller.

  • Coverage: Check whether a polygon completely covers the region.
  • Depth: Compare the depth of candidate surfaces over the region.
  • Ambiguity: If the available tests cannot determine one visible surface for the entire region, subdivide it.

6.6 Advantages

  • Large areas can be classified together instead of testing every pixel separately.
  • Only ambiguous regions need further subdivision.
  • It can be efficient when large parts of the screen are covered by one surface or by the background.
  • The hierarchical subdivision structure makes the process systematic.

6.7 Limitations

  • Repeated subdivision can create many small regions in complex scenes.
  • Intersecting or closely overlapping surfaces may cause extensive subdivision.
  • Additional work is needed to test polygon coverage and depth within each region.
  • In the worst case, subdivision may continue down to individual pixels, reducing the advantage of processing large areas together.

6.8 Exam-Oriented Answer

The area-subdivision algorithm is an image-space hidden-surface removal method. It starts with the complete viewing area and tests the polygons overlapping it. If the area is uncovered, the background is displayed. If one surface is definitely visible throughout the area, that surface is displayed. If visibility is ambiguous because multiple surfaces overlap, the area is divided into four smaller regions. The same procedure is repeated for each subregion until visibility is resolved or the region becomes a pixel. This method is efficient when large regions can be classified together, but complex scenes may require repeated subdivision.

7.1 Meaning of an Octree

An octree is a hierarchical tree structure used to represent and organize objects or data in three-dimensional space. Each internal node can be divided into at most eight child regions, called octants.

In visible-surface determination, the viewing volume is represented using octree nodes. The nodes are projected onto the viewing plane in a suitable front-to-back order so that nearer surfaces are processed before farther surfaces.

7.2 How 3D Space Is Divided

  • Begin with a cube or a 3D bounding region containing the scene.
  • Divide the region into eight smaller 3D regions by splitting it along the x, y and z directions.
  • Each smaller region is an octant and is represented by a child node.
  • If a region still needs more detail, subdivide it again into eight smaller regions.
  • Continue until the required level of detail or voxel size is reached.

A smallest represented volume element is commonly called a voxel (volume element). An octree therefore stores a hierarchical description of the 3D volume rather than treating every location as an unrelated element.

7.3 Octree for Visible-Surface Determination

For hidden-surface removal, the octree nodes are visited in an order that processes the regions nearest to the viewer before the regions behind them. For a particular viewing direction, the four front octants are processed before the four rear octants. The same front-to-back ordering is applied recursively inside each subdivided octant.

When a node contains a surface colour, its projected area is written to the corresponding frame-buffer area only if that area has not already received a colour from a nearer node. Thus, a farther node does not overwrite a pixel already assigned by a nearer surface.

7.4 Working Steps

  1. Represent the 3D viewing volume using an octree.
  2. Identify the order of the octants according to the viewing direction, from front to back.
  3. Traverse the octree recursively in that order, processing nearer child regions before farther child regions.
  4. Project each relevant node or voxel onto its corresponding area on the viewing plane.
  5. Check the corresponding frame-buffer area. If it has not yet been assigned a surface colour, write the current node's colour.
  6. If the projected area already contains a colour from a nearer node, do not overwrite it with the farther node's colour.
  7. Skip a node and its descendants when the node is completely obscured and cannot contribute visible pixels.
  8. Continue until all potentially visible nodes have been processed.

7.5 Example of Front-to-Back Processing

Suppose a viewing direction makes octants 0, 1, 2 and 3 the front group, while octants 4, 5, 6 and 7 are behind them. The algorithm processes the front group first. If a front octant paints a particular pixel area, a later rear octant cannot replace that colour.

Visibility rule

First visible colour written → keep it

Later farther colour → do not overwrite

The exact octant order depends on the viewing direction and the octree's numbering convention.

7.6 Difference Between Quadtree and Octree

BasisQuadtreeOctree
Space representedTwo-dimensional areaThree-dimensional volume
SubdivisionFour smaller regionsEight smaller regions
Basic unitArea or image regionVoxel or volume region
Typical use hereOrganizing subdivisions on the viewing planeOrganizing the 3D viewing volume for visibility processing

7.7 Advantages

  • Organizes 3D space hierarchically.
  • Front-to-back traversal helps process nearer surfaces first.
  • Completely hidden regions can be skipped, avoiding unnecessary processing of their descendants.
  • Supports different levels of spatial detail through recursive subdivision.

7.8 Limitations

  • Building and maintaining the tree requires additional memory and processing.
  • Complex or unevenly distributed scenes may require many subdivisions.
  • The traversal order must be selected correctly for the viewing direction.
  • Projection and visibility checks are still required for nodes that may contribute to the final image.

7.9 Exam-Oriented Answer

An octree is a hierarchical structure used to represent a three-dimensional viewing volume. Each node can be divided into eight smaller regions called octants. In visible-surface determination, octree nodes are projected onto the viewing plane in front-to-back order. The front octants are processed before the rear octants, and the same order is followed recursively. When a node's colour is projected onto the frame buffer, it is written only if the corresponding area has not already been filled by a nearer node. Completely obscured nodes can be skipped. This removes hidden surfaces and avoids processing regions that cannot affect the visible image.
