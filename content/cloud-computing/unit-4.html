Topic 1. Information Storage, Retrieval, Archive and Protection

YELLOWYELLOW priority · Official Unit IV · Topic 1 of 13

WHY STUDY THIS TOPIC?

Cloud computing depends on storing large amounts of information and making it available whenever users need it. Organisations must also preserve old records and protect data against loss, damage and unauthorised access.

How much depth is needed?

  • 1 mark: Understand storage, retrieval, archive and data protection.
  • 5 marks: Explain the four activities and their importance.
  • 15 marks: Understand the complete information-management process, its architecture, working, examples and benefits.

1.1 What is Information Storage in Cloud Computing?

Information storage is the process of saving digital data in a storage system so that it can be accessed and used whenever required.

In cloud computing, data is stored on remote servers managed by a cloud service provider instead of being stored only on the user's local computer.

Simple example: Google Drive

  1. You select the photograph on your mobile.
  2. The photograph is transferred through the internet.
  3. Google's cloud infrastructure stores the data.
  4. You can access it later from another device.

Figure 1: Cloud information storage working example

Main characteristics of cloud information storage

  1. Scalability: Storage capacity can be increased or decreased according to demand.
  2. Accessibility: Authorised users can access data over the internet or private networks.
  3. Durability: Storage systems are designed to preserve data reliably.
  4. Availability: Data can be made accessible when required.
  5. Security: Encryption and access controls help protect stored information.

1.2 Types of cloud storage

Cloud storage is commonly classified into three main types (with modern cloud-service examples to help understand the concepts):

Storage TypeHow Data is StoredUse CaseCloud Examples
1. Object Storage Stores data as objects, each with its own data, metadata and unique identifier Photographs, videos, backups and documents Amazon S3, Google Cloud Storage, Azure Blob Storage
2. Block Storage Divides data into fixed-sized blocks Disk storage for virtual machines (OS disk) and databases Amazon EBS, Azure Managed Disks
3. File Storage Stores data in a hierarchical structure of files and folders Shared office folders and team documents Amazon EFS, Azure Files

Figure 2: Classification of cloud storage into Object, Block, and File storage

1.3 What is Information Retrieval?

Information retrieval is the process of finding and accessing stored information when a user or application requests it.

In simple words, storing information means saving it; retrieving information means getting it back when needed.

Example: You open Google Drive and search for MCA_Assignment.pdf. Google Drive finds the file and allows you to open or download it.

How information retrieval works

Figure 3: Simplified information retrieval process

Important factors affecting retrieval

  • Search/indexing: Helps locate the required information.
  • Network speed: Affects how quickly data is transferred.
  • Storage performance: Affects how quickly the storage system responds.
  • Access permissions: Determine whether a user can retrieve particular data.
  • Retrieval latency: Time taken to obtain the requested information.

1.4 What is Information Archiving?

Information archiving is the process of moving inactive or rarely accessed data into long-term storage for future use.

Not all data is required every day. Organisations often need to preserve old records for legal, historical, business or compliance purposes.

Example: A college may use current-year student records regularly, while keeping examination records from ten years ago in archive storage.

1.5 What is Information Protection?

Information protection refers to the methods and technologies used to prevent data from being lost, damaged, stolen, modified or accessed by unauthorised users.

In cloud computing, protecting information is important because data is stored and accessed through network-connected infrastructure.

  • Encryption in transit: Protects data while it moves across a network.

1.7 Advantages

  1. Cost efficiency: Organisations can reduce investment in their own storage infrastructure.
  2. Scalability: Storage capacity can grow with business requirements.
  3. Accessibility: Users can access authorised information from different locations.
  4. Long-term preservation: Archives help retain historical and important records.

  6. Security: Encryption and access control reduce the risk of unauthorised access.

2.1 What is Cloud Analytics?

Cloud Analytics is the process of collecting, storing, processing and analysing data using cloud-based computing resources and analytical tools.

In simple words, Cloud Analytics helps organisations understand large amounts of data using cloud platforms instead of depending entirely on their own computers and servers.

Example: Online Shopping Company

Suppose an online shopping company receives thousands of orders every day. Using Cloud Analytics, it can analyse:

  • Which products are selling the most.
  • Which city has the highest number of customers.
  • Which products are frequently returned.
  • How customer purchasing behaviour changes over time.

2.2 How does Cloud Analytics work?

The process generally involves five steps:

  1. Data Collection: Collect data from websites, applications, databases and devices.
  2. Data Storage: Store data in cloud storage or a cloud data warehouse.
  3. Data Processing: Clean, organise and transform the collected data.
  4. Data Analysis: Apply analytical methods to identify patterns and trends.
  5. Visualisation and Reporting: Display results through charts, dashboards and reports.

  3. Data Processing: Cleans and transforms data.

  5. Visualisation Tools: Present results using charts and dashboards.

3.1 What is Testing Under Cloud?

Testing Under Cloud means using cloud-based infrastructure, platforms and tools to test software applications.

Instead of purchasing and maintaining physical testing servers, developers can use cloud resources to create testing environments whenever required.

Simple example: Online Shopping Website

Suppose you develop an online shopping website. Before releasing it, you need to check whether:

  • Users can log in successfully.
  • Products are displayed correctly.
  • Payments work properly.
  • The website can handle 10,000 users simultaneously.
  • User information is secure.

You can use cloud resources such as AWS or Microsoft Azure to perform these tests.

3.2 Why do we need Cloud Testing?

Consider a company that wants to test its application with 10,000 users. If it uses traditional infrastructure, it may need to purchase and maintain many physical servers, which is expensive. Cloud testing solves this problem by providing testing resources on demand.

  1. Cost reduction: No need to purchase expensive physical testing servers.
  2. Scalability: Increase or decrease testing resources as required.
  3. Flexibility: Create different testing environments easily.
  4. Accessibility: Testing teams can access resources from different locations.
  5. Faster testing: Multiple tests can run simultaneously.

3.3 Types of Cloud Testing

Different types of testing are performed to check different aspects of an application:

A. Functional Testing

Checks whether the application's features work according to requirements.

  • Example: Does login work? Can users add products to a cart? Does the payment process work?

B. Performance Testing

Checks how well an application performs under different workloads. Example: Testing whether a shopping website works properly when 10,000 users visit it simultaneously.

TypeMeaning
Load testingChecks performance under expected user load.
Stress testingChecks behaviour beyond normal capacity.
Scalability testingChecks whether the application can handle increasing workloads.

C. Security Testing

Checks whether the application and its data are protected against security threats.

  • Example: Can an unauthorised user access private information? Is sensitive data protected? Are authentication mechanisms working correctly?

D. Compatibility Testing

Checks whether the application works across different environments.

  • Example: Chrome, Firefox and Edge; Windows, Linux and macOS; different mobile devices.

E. Availability and Reliability Testing

Checks whether an application remains available and works correctly over time.

  • Example: Checking whether an application continues working when one server fails.

Figure 1: Five main categories of Cloud Testing

3.4 How Does Cloud Testing Work?

The general process follows six sequential stages:

  1. Requirements: Decide what needs to be tested.
  2. Test Planning: Prepare test cases and testing strategy.
  3. Create Cloud Environment: Provision cloud servers and testing tools.
  4. Execute Tests: Run functional, performance and security tests.
  5. Monitor and Analyse: Collect logs, errors and performance results.
  6. Report and Retest: Fix problems and test the application again.

Figure 2: Six-step Cloud Testing workflow

3.5 Advantages of Cloud Testing

  • Cost-effective: Reduces hardware and maintenance expenses.
  • Scalable: Resources can be increased or decreased.
  • Flexible: Different testing environments can be created.
  • Faster execution: Multiple testing activities can run simultaneously.
  • Global access: Teams can access testing environments remotely.

3.6 Challenges of Cloud Testing

  • Internet dependency: A stable internet connection is required.
  • Security concerns: Test data may contain sensitive information.
  • Network variability: Network delays can affect test results.
  • Cost management: Unused cloud resources may increase expenses.
  • Resource limitations: Cloud providers may impose usage limits.

3.7 Practical Example

Imagine an e-commerce company developing a shopping application on AWS. Before launching it, the company:

  1. Performs functional testing to check login and payment.
  2. Performs load testing to simulate thousands of users.
  3. Performs security testing to protect customer information.
  4. Performs compatibility testing on different browsers.
  5. Analyses the test reports and fixes errors.

After successful testing, the company releases the application.

4.1 What is Information Security?

Definition: Information Security is the process of protecting information and information systems from unauthorised access, use, disclosure, modification, destruction or disruption.

In simple words, Information Security ensures that only authorised people can access information and that the information remains safe and correct.

Example: In an online banking application, only you should access your account, your password should remain private, nobody should modify your account balance illegally, and your banking information should be available when needed. These protections come under Information Security.

4.2 Three Main Principles of Information Security — CIA Triad

The CIA Triad is one of the most important concepts in Information Security. It consists of three principles:

  • Confidentiality: Ensures that information is accessible only to authorised people. For example, only you can access your banking password.
  • Integrity: Ensures that information remains accurate and is not modified without permission. For example, nobody should change your bank balance illegally.
  • Availability: Ensures that information and services are available whenever authorised users need them. For example, your banking application should be available when you want to transfer money.

Easy way to remember: Confidentiality = Who can see the data? Integrity = Is the data correct? Availability = Can I access the data when needed?

Figure: The three principles of the CIA Triad

4.3 Why is Information Security Required in Cloud Computing?

In cloud computing, organisations store their data on infrastructure managed by cloud service providers, and users access that data through networks. This creates several security risks.

  1. Data protection: Protect sensitive information from theft or unauthorised access.
  2. Privacy: Ensure that personal and business information remains private.
  3. Prevent data modification: Stop unauthorised users from changing information.
  4. Business continuity: Keep cloud services available during failures and attacks.
  5. Regulatory compliance: Help organisations meet legal and industry security requirements.
  6. Customer trust: Maintain customer confidence in cloud services.

4.4 Primary Security Concerns in Cloud Computing

These are major problems that organisations must consider when using cloud services.

Understand with a simple example

Imagine a company stores customer information on a cloud server:

  • If an attacker steals customer records, it is a Data Breach.
  • If someone deletes the records, it is Data Loss.
  • If someone steals an employee's login credentials, it is Account Hijacking.
  • If storage permissions are set incorrectly, it is a Misconfiguration.
  • If attackers flood the website with requests, it is a Denial of Service.

4.5 Different Levels of Security in Cloud Computing

Cloud security is not provided through a single mechanism. Different layers protect different parts of the cloud environment. Four important levels are:

  1. Network-Level Security
  2. Host-Level Security
  3. Application-Level Security
  4. Data Security

Figure: Four complementary levels of cloud security

A. Network-Level Security

Definition: Network-Level Security protects communication networks and data travelling between users, servers and cloud resources. It prevents unauthorised network access and network-based attacks.

Common security methods:

  • Firewalls control incoming and outgoing network traffic.
  • VPN creates a protected connection over a network.
  • Network segmentation divides networks into separate sections.
  • Intrusion Detection System (IDS) detects suspicious network activity.
  • Intrusion Prevention System (IPS) detects and blocks certain malicious activity.
  • TLS protects data while it travels across a network.

Example: When you access a cloud application, a firewall can prevent unauthorised network traffic from reaching its servers.

B. Host-Level Security

Definition: Host-Level Security protects individual servers, virtual machines and operating systems running in a cloud environment. A host is a computer or server that runs applications and services.

Common security methods:

  • Operating system updates and security patches.
  • Antivirus and endpoint protection.
  • Strong user authentication.
  • Restricting administrator privileges.
  • Disabling unnecessary services and ports.
  • Monitoring server activities.

Example: A company runs its application on an AWS virtual machine. It updates the operating system and restricts administrator access to protect that server.

C. Application-Level Security

Definition: Application-Level Security protects software applications from vulnerabilities, attacks and unauthorised access. It focuses on securing the application itself.

Common security methods:

  • Input validation checks user input before processing it.
  • Authentication verifies user identity.
  • Authorisation controls what an authenticated user can do.
  • Secure coding reduces programming vulnerabilities.
  • API security protects application programming interfaces.
  • Regular security testing finds vulnerabilities before attackers exploit them.

Example: An online shopping website should not allow users to access another customer's order simply by changing an order ID in the URL.

D. Data Security

Definition: Data Security protects stored and transmitted information from unauthorised access, modification, disclosure or destruction.

Common security methods:

  • Encryption at rest.
  • Encryption in transit.
  • Access control and permissions.
  • Backup and recovery.
  • Data masking.
  • Data classification.

Example: A cloud database stores customer passwords securely using password hashing rather than storing plain-text passwords.

4.7 How Does Cloud Security Work?

Cloud Security works through multiple security controls that protect users, networks, servers, applications and data.

  1. User Authentication: Verify the user's identity using passwords, MFA or other methods.
  2. Authorisation: Check whether the user has permission to access the requested resource.
  3. Network Protection: Firewalls, VPNs and network controls protect communication.
  4. Server and Application Protection: Secure configurations, patches and application controls protect systems.
  5. Data Protection: Encryption, backup and access controls protect information.
  6. Monitoring and Detection: Logs and monitoring tools help detect suspicious activities.

Figure: Six controls used in a cloud security workflow

Practical example: When you log in to a cloud-based banking application, the application verifies your identity, checks your permissions, protects communication and operations, safeguards your account information, and records activities to help identify suspicious behaviour.

4.8 Shared Responsibility Model

Definition: The Shared Responsibility Model means that cloud security responsibilities are divided between the Cloud Service Provider (CSP) and the customer. The exact division depends on whether you use IaaS, PaaS or SaaS.

Cloud Provider's Responsibility

The provider generally protects the underlying cloud infrastructure, such as:

  • Physical data centres.
  • Physical servers.
  • Networking infrastructure.
  • Physical storage equipment.
  • Infrastructure facilities.

Customer's Responsibility

The customer is responsible for protecting resources and information they control, such as:

  • User accounts and permissions.
  • Passwords and authentication.
  • Data and its classification.
  • Application configuration.
  • Access policies.

Example: If you host an application on AWS EC2, AWS protects the physical data centre and underlying infrastructure. You are responsible for securing your EC2 operating system, application, user permissions and data.

Important: The responsibility boundary changes between IaaS, PaaS and SaaS. It is not correct to assume the provider handles all security.

Figure: Cloud provider and customer share security responsibilities

Authentication vs Authorisation

  • Authorisation: Are you allowed to perform this action?

Example: Logging in to a college portal using your credentials is authentication. Whether you can view student marks or modify them depends on authorisation.

4.11 Quick Revision

  • Information Security = Protecting information and systems.
  • CIA Triad = Confidentiality, Integrity and Availability.
  • Confidentiality = Only authorised people can see information.
  • Integrity = Information remains accurate.
  • Availability = Information is accessible when required.
  • Network-Level Security = Protects network communication.
  • Host-Level Security = Protects servers and operating systems.
  • Application-Level Security = Protects software applications.
  • Data Security = Protects stored and transmitted information.
  • Shared Responsibility Model = Security responsibilities are divided between CSP and customer.
