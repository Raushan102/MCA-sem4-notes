Topic 1. Information Storage, Retrieval, Archive and Protection

YELLOWYELLOW priority · Official Unit IV · Topic 1 of 13

WHY STUDY THIS TOPIC?

Cloud computing depends on storing large amounts of information and making it available whenever users need it. Organisations must also preserve old records and protect data against loss, damage and unauthorised access.

1.1 What is Information Storage in Cloud Computing?

Information storage is the process of saving digital data in a storage system so that it can be accessed and used whenever required.

In cloud computing, data is stored on remote servers managed by a cloud service provider instead of being stored only on the user's local computer.

Simple example: Google Drive

  1. You select the photograph on your mobile.
  2. The photograph is transferred through the internet.
  3. Google's cloud infrastructure stores the data.
  4. You can access it later from another device.

Figure 1: Cloud information storage working example

Main characteristics of cloud information storage

  1. Scalability: Storage capacity can be increased or decreased according to demand.
  2. Accessibility: Authorised users can access data over the internet or private networks.
  3. Durability: Storage systems are designed to preserve data reliably.
  4. Availability: Data can be made accessible when required.
  5. Security: Encryption and access controls help protect stored information.

1.2 Types of cloud storage

Cloud storage is commonly classified into three main types (with modern cloud-service examples to help understand the concepts):

1.3 What is Information Retrieval?

Information retrieval is the process of finding and accessing stored information when a user or application requests it.

In simple words, storing information means saving it; retrieving information means getting it back when needed.

Example: You open Google Drive and search for MCA_Assignment.pdf. Google Drive finds the file and allows you to open or download it.

Important factors affecting retrieval

  • Network speed: Affects how quickly data is transferred.
  • Storage performance: Affects how quickly the storage system responds.
  • Access permissions: Determine whether a user can retrieve particular data.
  • Retrieval latency: Time taken to obtain the requested information.

1.4 What is Information Archiving?

Information archiving is the process of moving inactive or rarely accessed data into long-term storage for future use.

Not all data is required every day. Organisations often need to preserve old records for legal, historical, business or compliance purposes.

Example: A college may use current-year student records regularly, while keeping examination records from ten years ago in archive storage.

Information protection refers to the methods and technologies used to prevent data from being lost, damaged, stolen, modified or accessed by unauthorised users.

In cloud computing, protecting information is important because data is stored and accessed through network-connected infrastructure.

2.1 What is Cloud Analytics?

Cloud Analytics is the process of collecting, storing, processing and analysing data using cloud-based computing resources and analytical tools.

In simple words, Cloud Analytics helps organisations understand large amounts of data using cloud platforms instead of depending entirely on their own computers and servers.

Example: Online Shopping Company

Suppose an online shopping company receives thousands of orders every day. Using Cloud Analytics, it can analyse:

  • Which products are selling the most.
  • Which city has the highest number of customers.
  • Which products are frequently returned.
  • How customer purchasing behaviour changes over time.

2.2 How does Cloud Analytics work?

The process generally involves five steps:

  1. Data Collection: Collect data from websites, applications, databases and devices.
  2. Data Storage: Store data in cloud storage or a cloud data warehouse.
  3. Data Processing: Clean, organise and transform the collected data.
  4. Data Analysis: Apply analytical methods to identify patterns and trends.
  5. Visualisation and Reporting: Display results through charts, dashboards and reports.

3.1 What is Testing Under Cloud?

Testing Under Cloud means using cloud-based infrastructure, platforms and tools to test software applications.

Instead of purchasing and maintaining physical testing servers, developers can use cloud resources to create testing environments whenever required.

Simple example: Online Shopping Website

Suppose you develop an online shopping website. Before releasing it, you need to check whether:

  • Users can log in successfully.
  • Products are displayed correctly.
  • Payments work properly.
  • The website can handle 10,000 users simultaneously.
  • User information is secure.

You can use cloud resources such as AWS or Microsoft Azure to perform these tests.

3.2 Why do we need Cloud Testing?

Consider a company that wants to test its application with 10,000 users. If it uses traditional infrastructure, it may need to purchase and maintain many physical servers, which is expensive. Cloud testing solves this problem by providing testing resources on demand.

  1. Cost reduction: No need to purchase expensive physical testing servers.
  2. Scalability: Increase or decrease testing resources as required.
  3. Flexibility: Create different testing environments easily.
  4. Accessibility: Testing teams can access resources from different locations.
  5. Faster testing: Multiple tests can run simultaneously.

3.3 Types of Cloud Testing

Different types of testing are performed to check different aspects of an application:

A. Functional Testing

Checks whether the application's features work according to requirements.

  • Example: Does login work? Can users add products to a cart? Does the payment process work?

B. Performance Testing

Checks how well an application performs under different workloads. Example: Testing whether a shopping website works properly when 10,000 users visit it simultaneously.

TypeMeaning

Stress testingChecks behaviour beyond normal capacity.

C. Security Testing

Checks whether the application and its data are protected against security threats.

  • Example: Can an unauthorised user access private information? Is sensitive data protected? Are authentication mechanisms working correctly?

D. Compatibility Testing

Checks whether the application works across different environments.

  • Example: Chrome, Firefox and Edge; Windows, Linux and macOS; different mobile devices.

E. Availability and Reliability Testing

Checks whether an application remains available and works correctly over time.

  • Example: Checking whether an application continues working when one server fails.

3.4 How Does Cloud Testing Work?

The general process follows six sequential stages:

  1. Requirements: Decide what needs to be tested.
  2. Test Planning: Prepare test cases and testing strategy.
  3. Create Cloud Environment: Provision cloud servers and testing tools.
  4. Execute Tests: Run functional, performance and security tests.
  5. Monitor and Analyse: Collect logs, errors and performance results.
  6. Report and Retest: Fix problems and test the application again.

Figure 2: Six-step Cloud Testing workflow

3.5 Advantages of Cloud Testing

  • Cost-effective: Reduces hardware and maintenance expenses.
  • Scalable: Resources can be increased or decreased.
  • Flexible: Different testing environments can be created.
  • Faster execution: Multiple testing activities can run simultaneously.
  • Global access: Teams can access testing environments remotely.

3.6 Challenges of Cloud Testing

  • Internet dependency: A stable internet connection is required.
  • Security concerns: Test data may contain sensitive information.
  • Network variability: Network delays can affect test results.
  • Cost management: Unused cloud resources may increase expenses.
  • Resource limitations: Cloud providers may impose usage limits.

3.7 Practical Example

Imagine an e-commerce company developing a shopping application on AWS. Before launching it, the company:

  1. Performs functional testing to check login and payment.
  2. Performs load testing to simulate thousands of users.
  3. Performs security testing to protect customer information.
  4. Performs compatibility testing on different browsers.
  5. Analyses the test reports and fixes errors.

After successful testing, the company releases the application.

4.1 What is Information Security?

Definition: Information Security is the process of protecting information and information systems from unauthorised access, use, disclosure, modification, destruction or disruption.

In simple words, Information Security ensures that only authorised people can access information and that the information remains safe and correct.

Example: In an online banking application, only you should access your account, your password should remain private, nobody should modify your account balance illegally, and your banking information should be available when needed. These protections come under Information Security.

4.2 Three Main Principles of Information Security — CIA Triad

The CIA Triad is one of the most important concepts in Information Security. It consists of three principles:

  • Confidentiality: Ensures that information is accessible only to authorised people. For example, only you can access your banking password.
  • Integrity: Ensures that information remains accurate and is not modified without permission. For example, nobody should change your bank balance illegally.
  • Availability: Ensures that information and services are available whenever authorised users need them. For example, your banking application should be available when you want to transfer money.

Easy way to remember: Confidentiality = Who can see the data? Integrity = Is the data correct? Availability = Can I access the data when needed?

Figure: The three principles of the CIA Triad

4.3 Why is Information Security Required in Cloud Computing?

In cloud computing, organisations store their data on infrastructure managed by cloud service providers, and users access that data through networks. This creates several security risks.

  1. Data protection: Protect sensitive information from theft or unauthorised access.
  2. Privacy: Ensure that personal and business information remains private.
  3. Prevent data modification: Stop unauthorised users from changing information.
  4. Business continuity: Keep cloud services available during failures and attacks.
  5. Regulatory compliance: Help organisations meet legal and industry security requirements.
  6. Customer trust: Maintain customer confidence in cloud services.

4.5 Different Levels of Security in Cloud Computing

Cloud security is not provided through a single mechanism. Different layers protect different parts of the cloud environment. Four important levels are:

  1. Network-Level Security
  2. Host-Level Security
  3. Application-Level Security
  4. Data Security

Figure: Four complementary levels of cloud security

A. Network-Level Security

Definition: Network-Level Security protects communication networks and data travelling between users, servers and cloud resources. It prevents unauthorised network access and network-based attacks.

Common security methods:

  • Firewalls control incoming and outgoing network traffic.
  • VPN creates a protected connection over a network.
  • Network segmentation divides networks into separate sections.
  • Intrusion Detection System (IDS) detects suspicious network activity.
  • Intrusion Prevention System (IPS) detects and blocks certain malicious activity.
  • TLS protects data while it travels across a network.

Example: When you access a cloud application, a firewall can prevent unauthorised network traffic from reaching its servers.

B. Host-Level Security

Definition: Host-Level Security protects individual servers, virtual machines and operating systems running in a cloud environment. A host is a computer or server that runs applications and services.

Common security methods:

  • Operating system updates and security patches.
  • Antivirus and endpoint protection.
  • Strong user authentication.
  • Restricting administrator privileges.
  • Disabling unnecessary services and ports.
  • Monitoring server activities.

Example: A company runs its application on an AWS virtual machine. It updates the operating system and restricts administrator access to protect that server.

C. Application-Level Security

Definition: Application-Level Security protects software applications from vulnerabilities, attacks and unauthorised access. It focuses on securing the application itself.

Common security methods:

  • Input validation checks user input before processing it.
  • Authentication verifies user identity.
  • Authorisation controls what an authenticated user can do.
  • Secure coding reduces programming vulnerabilities.
  • API security protects application programming interfaces.
  • Regular security testing finds vulnerabilities before attackers exploit them.

Example: An online shopping website should not allow users to access another customer's order simply by changing an order ID in the URL.

D. Data Security

Definition: Data Security protects stored and transmitted information from unauthorised access, modification, disclosure or destruction.

Common security methods:

  • Encryption at rest.
  • Encryption in transit.
  • Access control and permissions.
  • Backup and recovery.
  • Data masking.
  • Data classification.

Example: A cloud database stores customer passwords securely using password hashing rather than storing plain-text passwords.

4.7 How Does Cloud Security Work?

Cloud Security works through multiple security controls that protect users, networks, servers, applications and data.

  1. User Authentication: Verify the user's identity using passwords, MFA or other methods.
  2. Authorisation: Check whether the user has permission to access the requested resource.
  3. Network Protection: Firewalls, VPNs and network controls protect communication.
  4. Server and Application Protection: Secure configurations, patches and application controls protect systems.
  5. Data Protection: Encryption, backup and access controls protect information.
  6. Monitoring and Detection: Logs and monitoring tools help detect suspicious activities.

Figure: Six controls used in a cloud security workflow

Practical example: When you log in to a cloud-based banking application, the application verifies your identity, checks your permissions, protects communication and operations, safeguards your account information, and records activities to help identify suspicious behaviour.

4.8 Shared Responsibility Model

Definition: The Shared Responsibility Model means that cloud security responsibilities are divided between the Cloud Service Provider (CSP) and the customer. The exact division depends on whether you use IaaS, PaaS or SaaS.

Cloud Provider's Responsibility

The provider generally protects the underlying cloud infrastructure, such as:

  • Physical data centres.
  • Physical servers.
  • Networking infrastructure.
  • Physical storage equipment.
  • Infrastructure facilities.

Customer's Responsibility

The customer is responsible for protecting resources and information they control, such as:

  • User accounts and permissions.
  • Passwords and authentication.
  • Data and its classification.
  • Application configuration.
  • Access policies.

Example: If you host an application on AWS EC2, AWS protects the physical data centre and underlying infrastructure. You are responsible for securing your EC2 operating system, application, user permissions and data.

Important: The responsibility boundary changes between IaaS, PaaS and SaaS. It is not correct to assume the provider handles all security.

Virtual Desktop Infrastructure provides centrally managed desktop environments to users over a network. It is useful for understanding remote work, desktop virtualisation and centralised IT management.

5.1 What is Virtual Desktop Infrastructure (VDI)?

Virtual Desktop Infrastructure (VDI) is a technology in which desktop operating systems and applications run on central servers or cloud infrastructure, while users access their virtual desktops through a network using devices such as laptops, thin clients or tablets.

In simple words, the actual desktop runs on a remote server. The user's device displays that desktop and sends keyboard and mouse actions to the server.

Simple example: College Computer Lab

Suppose a college has 100 students who need the same operating system and software for practical classes. Instead of installing and maintaining a complete desktop setup on every computer, the college can host virtual desktops centrally. Students connect to their assigned desktops from lab terminals.

  • The college IT team manages desktop images and applications centrally.
  • Students access their desktops through the college network.
  • Processing takes place on the central server rather than entirely on the local terminal.

5.2 Why is VDI needed?

Traditional desktop systems require organisations to configure, update and maintain many individual computers. VDI provides a centrally managed alternative.

  1. Remote access: Employees can access their work desktop from different locations.
  2. Centralised management: IT administrators can manage desktop images, updates and settings from one place.
  3. Better control: Business data can remain in the central data centre instead of being stored on every endpoint device.
  4. Hardware flexibility: Users may access desktops through thin clients or less powerful devices.
  5. Easy deployment: New virtual desktops can be created from standard desktop images.

5.3 Main Components of VDI

A VDI environment contains several components that work together to deliver a desktop to the user.

2. HypervisorSoftware layer that creates and manages multiple virtual machines on a physical server.
3. Virtual Machine (VM)Software-based computer that runs the desktop operating system and applications for a user.
4. Connection BrokerAuthenticates users and connects them to an appropriate virtual desktop.
5. Centralised StorageStores desktop images, applications, user profiles and data.
6. Client DeviceDevice used by the person to access the desktop, such as a PC, laptop, tablet or thin client.
7. Remote Display ProtocolTransfers the desktop display to the client and sends user input back to the virtual desktop.

5.4 How Does VDI Work?

  1. Desktop creation: The administrator prepares a desktop image containing an operating system and required applications.
  2. Virtualisation: The hypervisor creates virtual machines using the resources of the host server.
  3. User login: The user opens a VDI client and provides login credentials.
  4. Authentication and connection: The connection broker verifies the user and assigns an available or personal virtual desktop.
  5. Desktop delivery: The remote display protocol sends the desktop screen to the user's device.
  6. User interaction: Keyboard and mouse actions are sent back to the virtual machine, where applications execute.
  7. Session ending: When the user logs out, the desktop is saved or reset according to the VDI type and organisation's settings.

5.5 Types of VDI

VDI is commonly divided into two main types according to whether user changes are saved between sessions.

A. Persistent VDI

Persistent VDI provides each user with a dedicated virtual desktop. The user's settings, installed applications and supported changes are retained for future sessions.

  • Each user generally returns to the same desktop.
  • Personal settings and changes can be saved.
  • Suitable for developers, designers and employees who need a customised environment.

B. Non-Persistent VDI

Non-persistent VDI provides a standard desktop from a common pool. After the session ends, the desktop is usually reset to its original state, so user changes are not retained on that desktop.

  • Users receive a standard or fresh desktop session.
  • It is easier to maintain because administrators manage a common image.
  • Suitable for call centres, training labs, libraries and shared workstations.

5.6 Advantages of VDI

  1. Centralised administration: Administrators can manage desktops, applications and updates centrally.
  2. Remote accessibility: Users can access their work environment from different locations using supported devices.
  3. Data control: Data can remain in central infrastructure, reducing the amount stored on endpoint devices.
  4. Scalability: Organisations can add or remove virtual desktops according to demand.
  5. Consistent environment: Standard desktop images help provide similar software and settings to users.
  6. Device flexibility: Users may connect through thin clients and other compatible devices.

5.7 Limitations and Challenges of VDI

  • Network dependency: A stable network connection is important for a good user experience.
  • Initial setup: Planning and deploying servers, storage and VDI software can be complex.
  • Infrastructure cost: Servers, storage, licences and support may require significant investment.
  • Performance issues: Insufficient server resources or network delays can make desktops slow.
  • Central point of failure: If key central infrastructure becomes unavailable, many users may lose access until service is restored.
  • Administration skills: Skilled IT staff are needed to manage and troubleshoot the environment.

5.8 Uses of VDI

  • Educational institutions: Provide standard desktops in computer labs and training centres.
  • Businesses: Give employees secure access to office desktops while working remotely.
  • Call centres: Provide standard desktops to large groups of agents.
  • Healthcare organisations: Give authorised staff access to required applications from different workstations.
  • Temporary workers: Quickly provide controlled desktop environments to contractors and short-term staff.

Topic 7. Resiliency

RED RED priority · Official Unit IV · Topic 7 of 13

7.1 What is Resiliency?

Explanatory definition: Resiliency in cloud computing is the ability of a cloud system to withstand unexpected problems, keep its important services running as far as possible, and recover its data and operations quickly when a failure causes disruption. It is achieved by preparing backup resources, keeping copies of important data, detecting failures and following a recovery plan.

In easy words, a resilient cloud system is prepared for problems. If one server stops, another server can take over. If data or a complete system is damaged, saved copies and a recovery plan help bring the service back.

Definition to write in the examination — “What is Resiliency?”

Resiliency in cloud computing refers to the ability of a cloud system to continue providing essential services during unexpected failures and to recover its data and normal operations quickly after a disruption. It is achieved through methods such as backup, data replication, redundancy, failover and disaster recovery planning.

Example: A college runs its student portal on the cloud. During exam form submission, one server suddenly stops. A second server takes over so students can continue using the portal. If a major failure damages the portal data, the college uses its saved backup to restore it. These arrangements make the service resilient.

7.2 Why is Resiliency Important?

A cloud service may stop working because of different problems:

  • Hardware problem: A physical part, such as a server or storage disk, stops working.
  • Software problem: An application or operating system crashes or gives errors.
  • Network problem: The connection between users and the cloud becomes unavailable.
  • Power failure: A data centre loses its power supply.
  • Cyberattack: Someone attacks the system and damages data or blocks access to it.
  • Natural disaster: Flood, fire or another disaster affects the building or data centre.

Resiliency reduces the effect of these problems. It helps avoid long service stoppages, protects important data and allows an organisation to continue its work.

7.3 Four Important Concepts of Resiliency

1. Fault Tolerance

Meaning: Fault tolerance is the ability of a system to keep working even when one of its parts fails.

Easy example: A cloud application runs on two working servers. If one server fails, the other server continues the work. The user may not even notice the problem.

2. High Availability

Meaning: High availability means keeping a service available to users almost all the time, with very little time when it cannot be used.

Easy example: An online shopping website uses more than one server. If the main server stops, requests are sent to another server. There may be a short delay, but the website becomes available again quickly.

3. Disaster Recovery

Meaning: Disaster Recovery means bringing back data, applications and computer systems after a serious event such as a fire, major cyberattack or data-centre failure.

Easy example: If a college's main data centre is damaged, the IT team uses backup data and another location to restore the student portal.

4. Business Continuity

Meaning: Business continuity means keeping the most important work of an organisation running during a problem.

Easy example: Even if a bank's main office faces a technical problem, customers should still be able to use important banking services through another working system or branch.

7.4 Methods Used to Make Cloud Systems Resilient

  1. Redundancy — keeping an extra part: Keep an extra server, network connection or storage device ready. If the main part fails, the extra part can be used.
  2. Replication — keeping another copy: Store another copy of important data or an application on a different server or location. If one copy is damaged or unavailable, the other copy may still be used.
  3. Load balancing — sharing the work: Send user requests to different servers instead of sending all requests to one server. This prevents one server from becoming too busy.
  4. Backup — saving data for later use: Make regular copies of important files and databases. If the original data is lost or damaged, the saved copy can be used.
  5. Failover — switching to a backup: When the main server stops working, the system moves the work to another working server. This switch may happen automatically.
  6. Monitoring — checking the system: Regularly check servers, applications and networks so that problems can be found early.
  7. Testing the recovery plan: Practise restoring data and switching to backup systems. This checks whether the plan will work during a real failure.

7.5 How Resiliency Works in a Cloud System

  1. Prepare: Identify important applications and data. Keep extra servers and backup copies ready.
  2. Watch the system: Check whether servers, applications and networks are working properly.
  3. Find the failure: Detect when a server, application or network stops working.
  4. Continue the service: Use another working server or connection so users can continue their work.
  5. Restore what was damaged: If there is a major failure, use saved data and the recovery plan to bring the system back.
  6. Check everything: Test the restored system and improve the plan if needed.

7.6 Disaster Recovery Plan

Definition: A Disaster Recovery Plan is a written set of steps that explains how an organisation will bring back its data, applications and computer systems after a major failure.

A good plan includes:

  • List important systems: Decide which applications and data must be restored first.
  • Keep backups: Save copies of important data in a safe place, preferably away from the main system.
  • Choose a recovery location: Decide where the systems will run if the main data centre is not available.
  • Give people responsibilities: Decide who will restore systems, contact users and check the results.
  • Decide the recovery time: Set how long the organisation can manage without each important service.
  • Test the plan: Practise the steps regularly and update the plan when systems change.

7.7 Two Important Recovery Terms — RTO and RPO

  • RTO (Recovery Time Objective): The maximum time an organisation can accept for bringing a service back after it stops. Example: If the RTO is 2 hours, the service should be restored within 2 hours.
  • RPO (Recovery Point Objective): The maximum amount of recent data an organisation can accept losing, measured in time. Example: If the RPO is 30 minutes, the organisation should have a saved copy that is no more than 30 minutes old. It may lose up to 30 minutes of recent changes.

8.1 Meaning of Cloud Provisioning

Definition: Cloud provisioning is the process of selecting, setting up and making cloud resources available to a user or application according to its needs.

Example: A college wants to launch an online admission portal. It needs a server to run the portal, storage to save student forms, and a network connection so students can access it. Arranging these resources from a cloud provider is called cloud provisioning.

8.2 Resources Provided Through Provisioning

  • Computing resources: Virtual machines and processing power needed to run applications.
  • Storage resources: Space to save files, databases, images and records.
  • Network resources: Connections that allow users, servers and applications to communicate.
  • Software resources: Operating systems, databases and applications needed by users.
  • Security resources: User accounts, access permissions and security settings that help protect the system.

8.3 Types of Cloud Provisioning

1. Static Provisioning (Advance Provisioning)

In static provisioning, the required resources are selected and arranged in advance. The amount of resources usually stays fixed until an administrator changes it.

Example: A college books a cloud server with a fixed amount of memory and storage for its student portal for the whole semester.

Suitable for: Applications whose resource needs are mostly known and do not change much.

2. Dynamic Provisioning (On-Demand Provisioning)

In dynamic provisioning, cloud resources are added or reduced according to the current need of the application. This helps the application handle busy and quiet periods.

Example: During admission season, many students visit the college portal. Extra server capacity is added. When the rush is over, the extra capacity is reduced.

Suitable for: Applications whose number of users or workload changes often.

3. Self-Service Provisioning

In self-service provisioning, users arrange the cloud resources they need through an online dashboard or portal, without waiting for the cloud provider's staff to set up each resource manually.

Example: A developer signs in to a cloud website, selects a virtual machine size and creates it for testing an application.

8.4 Steps in the Provisioning Process

  1. Identify the need: Decide what application or work will use the cloud resources.
  2. Choose the resources: Select the required server power, storage, network and software.
  3. Select the size: Decide how much CPU, memory and storage are needed.
  4. Set up the resources: Create the server, storage, network and other required services.
  5. Configure access and security: Create user access and apply suitable security settings.
  6. Test the setup: Check that the application works correctly.
  7. Monitor and adjust: Watch resource use and add or remove resources when needed.

9.2 What are Cloud Assets?

A cloud asset is any cloud resource, service or software item that an organisation uses or pays for.

  • Computing assets: Virtual machines and cloud servers that run applications.
  • Storage assets: Cloud disks, storage buckets and databases that hold information.
  • Network assets: Virtual networks, firewalls and load balancers that connect and protect systems.
  • Software assets: Applications, operating systems and software licences used in the cloud.
  • Security assets: User accounts, access rules, security keys and certificates used to protect cloud resources.

9.3 Why is Cloud Asset Management Needed?

  • Know what the organisation owns or uses: Keep a clear list of cloud resources.
  • Avoid waste: Find unused servers, storage or services that are still costing money.
  • Control cost: Understand which department or application is using each resource.
  • Improve security: Find unknown resources and check who can access them.
  • Manage software licences: Check that software is being used according to its licence rules.
  • Support audits: Provide records when the organisation needs to check its resources, spending or security.

9.4 Main Activities in Cloud Asset Management

  1. Asset discovery: Find all cloud resources being used by the organisation, including resources created by different teams.
  2. Asset inventory: Prepare and maintain a list of resources. Record details such as resource name, type, location, owner and purpose.
  3. Classification and tagging: Group resources by department, project, application or importance. A tag is a small label added to a resource to identify it.
  4. Ownership tracking: Record the person or team responsible for each resource.
  5. Usage monitoring: Check how much computing power, storage and network capacity each resource uses.
  6. Cost tracking: Check the cost of each resource and find resources that are not being used properly.
  7. Security and licence checks: Check access permissions, security settings and software licence use.
  8. Removal of unused resources: Close or delete resources that are no longer required, after checking that important data is safe.
  9. Reporting: Prepare reports about resources, usage, cost and security.

9.5 Cloud Asset Management Life Cycle

  1. Plan or request: A team identifies a need for a cloud resource.
  2. Create or acquire: The required cloud resource is created or purchased.
  3. Record: Add the resource to the asset list with its name, owner, purpose and cost details.
  4. Use and monitor: Track its use, performance, cost and security while it is active.
  5. Review: Check whether the resource is still needed and whether it is being used correctly.
  6. Remove safely: When it is no longer needed, save required data and then close or delete the resource.

9.6 Benefits of Cloud Asset Management

  • Better visibility: The organisation knows which cloud resources are being used.
  • Lower cost: Unused or unnecessary resources can be identified and removed.
  • Better security: Unknown resources and incorrect access can be found more easily.
  • Better use of resources: Resources can be assigned to the teams and applications that need them.
  • Easy reporting: Records help with audits, budgeting and management decisions.
  • Licence control: Software use can be checked against licence conditions.

9.7 Problems in Cloud Asset Management

  • Many resources: Large organisations may use hundreds or thousands of cloud resources.
  • Resources change often: Teams can create, change or remove resources at any time, so records must be updated.
  • Different cloud providers: An organisation using more than one provider may need to check resources in different systems.
  • Unknown resources: Employees may create resources without informing the IT team. These are sometimes called shadow IT.
  • Cost tracking: It may be difficult to connect every cloud bill with the team or application that used the resource.

9.8 Example of Cloud Asset Management

Suppose a college uses cloud services for its website, student portal, online classes and student records. The IT team prepares a list of all servers, databases, storage and software licences. Each resource is labelled with the department and person responsible for it. The team checks usage and monthly cost. If an old testing server is no longer needed, the team saves any required data and removes the server. This helps the college avoid waste, control cost and keep its cloud resources organised.

Topic 10. Cloud Governance

10.1 Meaning and Definition

Explanatory definition: Cloud Governance is the system of rules, policies, responsibilities and processes an organisation uses to guide and control how cloud services are selected, accessed, used, secured and paid for. It makes sure that cloud resources support the organisation's goals while meeting its security, legal, performance and budget requirements.

In simple words: Cloud governance means setting clear rules for using the cloud, deciding who is responsible, and checking that everyone follows those rules.

Exam-ready definition — What is Cloud Governance?

Cloud Governance is a framework of policies, rules, roles and processes used by an organisation to manage and control its cloud resources. It ensures that cloud services are used securely, efficiently and within the organisation's legal, operational and financial requirements.

10.2 Why is Cloud Governance Needed?

  • Security: It controls who can access cloud resources and helps prevent unauthorised use.
  • Cost control: It sets budgets, spending limits and approval rules to avoid unnecessary cloud expenses.
  • Legal compliance: It helps the organisation follow laws, regulations and industry rules related to data and privacy.
  • Consistency: It ensures that different teams follow common standards when creating and managing cloud resources.
  • Risk reduction: It helps identify risks such as public data exposure, weak passwords and unused accounts.
  • Accountability: It clearly assigns responsibility to people and teams.

10.3 Main Areas of Cloud Governance

  1. Security and identity management: Define who can sign in and what each user is allowed to do. Use strong authentication and give only the permissions required for a person's work.
  2. Data governance: Decide how data is classified, stored, shared, backed up and deleted. Sensitive information may need stronger protection and restricted locations.
  3. Cost and financial management: Set budgets, monitor spending, use resource tags and review bills regularly.
  4. Resource management: Set standards for naming, creating, configuring and removing cloud resources. This prevents disorder and waste.
  5. Compliance and audit: Check whether cloud services follow applicable laws, policies and internal standards. Keep records that can be examined later.
  6. Risk management: Identify possible problems, estimate their impact and decide how to prevent or reduce them.
  7. Performance and availability: Set service expectations and monitor whether cloud systems meet them.
  8. Vendor and service management: Review provider services, contracts, service-level agreements and dependence on a single provider.

10.4 Principles of Effective Cloud Governance

  • Clear policies: Rules should be written in a way that employees can understand and follow.
  • Defined roles: Every important task should have an assigned owner.
  • Least privilege: Users should receive only the access needed to do their jobs.
  • Automation: Use automated rules to apply approved settings and detect policy violations.
  • Continuous monitoring: Review security, spending, performance and compliance regularly.
  • Regular improvement: Update policies when business needs, technology or laws change.

10.5 Cloud Governance Working Process

  1. Understand requirements: Identify business goals, data sensitivity, legal requirements and expected costs.
  2. Create policies: Write rules for access, security, data storage, resource creation, budgets and compliance.
  3. Assign responsibilities: Decide which teams approve, operate and review cloud services.
  4. Apply controls: Configure access permissions, security settings, budgets, tags and approved resource templates.
  5. Monitor cloud use: Collect records about user actions, resource use, cost and security events.
  6. Review and correct: Find policy violations or waste, correct them and update the rules when needed.

10.6 Example

Suppose a college uses cloud services for student records, online examinations and its website. Governance rules may require that only authorised staff can open student records, backups are kept, cloud spending is reviewed every month, and departments use approved resource settings. If a team creates a public storage folder by mistake, monitoring can detect it and the responsible team can correct it.

10.7 Benefits of Cloud Governance

  • Improves security and protection of information.
  • Helps meet legal and organisational requirements.
  • Controls cloud spending and reduces waste.
  • Makes responsibilities and approval processes clear.
  • Creates consistent cloud practices across departments.
  • Improves visibility, audit records and management decisions.

10.8 Challenges

  • Changing cloud services: Policies must keep up with new services and features.
  • Multiple teams: Different teams may follow different practices unless rules are clearly communicated.
  • Complex compliance: Organisations may need to meet several legal and industry requirements.
  • Balancing control and speed: Too many approvals can slow work, while too few controls can increase risk.
  • Multi-cloud management: Applying consistent rules across different providers can be difficult.

Topic 11. High Availability and Disaster Recovery

BLACK BLACK priority · Official Unit IV · Topic 11 of 13

Exam focus: Understand the meaning of high availability and disaster recovery, their difference, common techniques and important recovery terms.

11.1 High Availability (HA)

Explanatory definition: High Availability is the ability of a computer system, application or cloud service to remain accessible and continue providing its service for as much time as possible, even when a component fails or maintenance is required. It is usually achieved by using backup components, more than one server and automatic switching to a working component.

Exam-ready definition — What is High Availability?

High Availability is the ability of a system to remain operational and accessible with very little interruption, even when one or more components fail. It is achieved through redundancy, monitoring and failover mechanisms.

Example: An online shopping website runs on two servers. If one server stops working, a load balancer sends users to the other server so that the website remains available.

11.2 Disaster Recovery (DR)

Explanatory definition: Disaster Recovery is the planned process of restoring applications, systems, data and IT services after a major event has disrupted normal operations. The event may be a cyberattack, accidental deletion, hardware failure, power outage or natural disaster. The plan explains how systems will be recovered and how quickly important services must return.

Exam-ready definition — What is Disaster Recovery?

Disaster Recovery is the set of plans, procedures and resources used to restore IT systems, applications and data after a major disruption so that normal business operations can resume.

11.3 Need for High Availability and Disaster Recovery

  • Reduce service downtime and keep important applications accessible.
  • Protect business data from loss or damage.
  • Continue important work during hardware, software or network failures.
  • Reduce financial loss and protect the organisation's reputation.
  • Restore services after major incidents such as cyberattacks or natural disasters.
  • Meet service commitments and business continuity needs.

11.4 Techniques Used

  1. Redundancy: Keep extra servers, network links or storage components so another can work if one fails.
  2. Data replication: Maintain copies of data on another server or location. Replication can be synchronous (copies updated together) or asynchronous (the second copy is updated after a short delay).
  3. Load balancing: Share incoming user requests across multiple servers to avoid overloading one server.
  4. Automatic failover: Move work from a failed component to a healthy backup component.
  5. Backups: Save copies of important data so it can be restored if the original is lost or damaged.
  6. Geographic distribution: Place systems or copies in different locations so one local disaster does not affect everything.
  7. Monitoring and alerts: Detect failures quickly and inform the responsible team.
  8. Recovery testing: Practise restoring systems to check that the plan works.

11.5 Disaster Recovery Process

  1. Identify critical services: Decide which applications and data must be restored first.
  2. Assess risks: Identify possible failures and their likely effects.
  3. Set recovery targets: Decide acceptable recovery time and data loss.
  4. Prepare backups and alternate resources: Keep copies of data and a recovery environment ready.
  5. Detect and declare the incident: Confirm the disruption and start the recovery plan.
  6. Restore systems and data: Bring back applications, networks and information in the planned order.
  7. Test and resume operations: Check that services work correctly before users return.
  8. Review the incident: Record lessons and improve the recovery plan.

11.6 Important Terms: RTO and RPO

RPO — Recovery Point ObjectiveThe maximum acceptable amount of data loss measured in time.RPO of 15 minutes means the organisation can accept losing at most 15 minutes of recent data.

11.8 Example

A bank runs its mobile banking application across multiple cloud servers. If one server fails, traffic moves to another server; this is high availability. If a major incident damages the primary environment, the bank uses replicated data and its disaster recovery plan to restore the application in another location.

11.9 Benefits and Limitations

Benefits: less downtime, better service continuity, reduced data loss, improved customer trust and faster recovery.

Limitations: extra servers and backup locations increase cost; setup and testing need skilled staff; replication may copy accidental changes or corrupted data; recovery plans become outdated if they are not reviewed.

Topic 12. Charging Models

YELLOW YELLOW priority · Official Unit IV · Topic 12 of 13

Exam focus: Learn the meaning of cloud charging, common pricing models, factors that affect cost and a simple comparison of the models.

12.1 Meaning and Definition

Explanatory definition: A Cloud Charging Model is the method a cloud service provider uses to calculate how much a customer must pay for cloud resources and services. The charge may depend on the amount of computing time, storage, network use, number of users, selected service level or length of commitment.

Exam-ready definition — What is a Cloud Charging Model?

A Cloud Charging Model is a pricing method used by a cloud provider to calculate the cost of services consumed by a customer, based on factors such as resource usage, time, storage, users or subscription period.

Simple example: If a company rents a cloud server for 10 hours, stores 100 GB of files and transfers data over the internet, its bill may include charges for all three activities.

12.2 Why are Charging Models Used?

  • To calculate the cost of cloud resources used by each customer.
  • To allow customers to choose a payment method that suits their needs.
  • To support flexible use of computing and storage resources.
  • To help organisations plan budgets and compare providers.
  • To connect the cost with actual usage or selected service commitments.

12.3 Main Cloud Charging Models

  1. Pay-as-you-go (usage-based): The customer pays for the resources actually used, such as server time, storage or data transfer. It is flexible and useful when demand changes, but costs may be difficult to predict.
  2. Subscription-based: The customer pays a fixed amount for a service over a period, such as monthly or yearly. It is common in SaaS applications and makes regular costs easier to plan.
  3. Reserved or commitment-based: The customer agrees to use or pay for a resource for a longer period, often in return for a lower rate. It suits workloads that are expected to run regularly.
  4. Spot or spare-capacity pricing: The customer uses unused provider capacity at a lower and sometimes changing price. The provider may interrupt or reclaim this capacity, so it is best for tasks that can pause and restart.
  5. Per-user pricing: The customer pays according to the number of people using the service. It is common for business software such as email or collaboration tools.
  6. Tiered or volume-based pricing: The price per unit changes according to usage levels. Higher usage may qualify for a lower rate, depending on the provider's plan.
  7. Freemium or free-tier model: A limited level of service is offered free, while extra capacity or features require payment.

12.5 Factors Affecting Cloud Charges

  • Compute: Type, size and running time of virtual machines or processing services.
  • Storage: Amount of data stored, storage type and how often data is accessed.
  • Network transfer: Amount of data sent between services or out to the internet.
  • Service level: Extra features such as backup, monitoring, security or managed support.
  • Location: Prices may differ by cloud region.
  • Commitment and discounts: Contract length, payment method and eligible discounts can change the final price.

12.6 How to Choose a Charging Model

  1. Estimate how much computing, storage and network capacity is needed.
  2. Check whether usage is steady or changes frequently.
  3. Decide whether flexibility or predictable monthly cost is more important.
  4. Compare provider rates, service limits and extra charges.
  5. Review actual bills regularly and change the plan if usage changes.

12.7 Advantages and Disadvantages

Advantages: flexible payment choices, lower initial investment, payment linked to use in usage-based plans, easier scaling and options for predictable costs.

Disadvantages: bills may rise unexpectedly, pricing can be complex, long commitments may not suit changing needs, and low-cost spot resources may be interrupted.

12.8 Example

A college uses a cloud learning platform. It pays a monthly subscription for each teacher account, uses pay-as-you-go servers during examination periods, and stores archived course videos in low-cost storage. Different charging models can be combined to match different needs.

Explanatory definition: Cloud Metering is the process of measuring and recording how much of a cloud service a customer uses. It collects information such as server running time, storage consumed, number of requests, active users or data transferred. Exam-ready definition — What is Cloud Metering?

Cloud Metering is the process of measuring and recording a customer's consumption of cloud resources and services, such as computing time, storage, network transfer and service requests.

13.2 Usage Reporting

Explanatory definition: Usage Reporting is the process of presenting collected cloud usage information in an organised form, usually through reports, tables or charts. It helps customers and administrators understand which services were used, how much was consumed, when usage occurred and which project or department used the resources.

Exam-ready definition — What is Usage Reporting?

Usage Reporting is the preparation and presentation of information about cloud resource consumption over a selected period to help users monitor, analyse and control their cloud usage.

13.3 Billing

Explanatory definition: Cloud Billing is the process of calculating the amount a customer must pay for cloud services during a billing period. It uses measured usage, the provider's pricing rules, subscriptions, discounts, taxes and other applicable charges to prepare an invoice or bill.

Exam-ready definition — What is Cloud Billing?

Cloud Billing is the process of calculating and charging customers for cloud services they have used, according to the provider's pricing rules and billing period.
