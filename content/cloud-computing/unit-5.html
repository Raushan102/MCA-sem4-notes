THE CENTRAL IDEA

1. Virtualization Defined

YELLOW Start here: almost every later topic in this unit is built on this idea.

1.1 Meaning and definition

Virtualization is the technology of creating a software-based (virtual) version of a computing resource—such as a server, operating system environment, storage device or network—so that multiple logical environments can use the resources of the same physical infrastructure.

In simple words, virtualization allows one physical machine to act like several separate machines. Each virtual machine can run its own operating system and applications, while a software layer manages how the physical resources are shared.

Everyday example: Imagine a large apartment building. The building is one physical structure, but it contains many independent flats. Each flat has its own occupants and private space, while all flats share the building's foundation, lifts and water supply. A physical server is like the building; virtual machines are like the flats; the hypervisor manages the shared foundation and resources.

1.2 Important terms

TermMeaning
Physical machine / HostThe real computer or server that contains the processor, RAM, disks and network interfaces.
Virtual Machine (VM)A software-defined computer with virtual CPU, memory, disk and network devices. It behaves like an independent computer.
Guest OSThe operating system installed inside a VM, such as Windows Server or Linux.
Host OSThe operating system of the physical computer in a hosted (Type 2) hypervisor arrangement.
Hypervisor / VMMSoftware or firmware that creates and runs VMs and controls their access to physical resources. VMM means Virtual Machine Monitor.
Virtual resourceA resource presented to a VM, such as virtual CPU, virtual RAM, virtual disk or virtual network adapter.
Guest / Host isolationSeparation that helps prevent one VM from directly interfering with another VM or the host.

1.3 Basic architecture of virtualization

Figure 1: Basic virtualization stack. Several VMs share one physical host through the hypervisor. Each VM has its own guest operating system and applications.

1.4 How virtualization works — in order

  1. The administrator installs or enables a hypervisor on a physical server.
  2. The hypervisor detects and manages the host's CPU, memory, storage and network devices.
  3. The administrator creates a VM and assigns virtual hardware, such as 4 virtual CPUs, 8 GB RAM and a virtual disk.
  4. An operating system is installed inside that VM. This becomes the guest OS.
  5. When the guest OS requests CPU time, memory or I/O, the hypervisor manages or mediates access to the underlying physical resources.
  6. Multiple VMs can run at the same time, subject to the capacity and configuration of the physical host.

Important distinction: A VM is not simply a folder or a second user account. It is an isolated computing environment with virtual hardware and its own operating system.

2. Virtualization Benefits

2.1 Major benefits

  1. Better resource utilisation: several workloads can share a powerful server instead of leaving many separate servers underused.
  2. Server consolidation: multiple physical servers can be replaced by fewer high-capacity hosts running multiple VMs.
  3. Lower cost: consolidation can reduce hardware purchases, electricity, cooling, rack space and maintenance effort.
  4. Isolation: workloads run in separate VMs, helping contain faults and separate environments when configured correctly.
  5. Flexibility and scalability: administrators can create, resize or remove VMs more easily than purchasing and installing new physical servers.
  6. Faster deployment: a VM can be created from a prepared image or template in a short time.
  7. Portability: VM files and images can often be copied, migrated or restored on compatible infrastructure.
  8. Testing and development: developers can run different operating systems and test environments on one computer.
  9. Backup and recovery: snapshots, images and replication can help protect workloads; a snapshot alone is not a complete backup strategy.
  10. Business continuity: VMs can be restarted or moved to another suitable host when supported by the platform and architecture.

2.2 Limitations and challenges

  • Performance overhead: virtualisation adds management layers; poorly designed workloads may experience latency or resource contention.
  • Resource contention: too many VMs competing for CPU, RAM, disk I/O or network bandwidth can slow each other down.
  • Single-host failure impact: if one physical host fails, several VMs on it may be affected unless high availability and recovery are configured.
  • Management complexity: virtual environments require monitoring, patching, capacity planning and skilled administration.
  • Security risks: a compromised hypervisor or weakly isolated VM environment can affect multiple workloads.
  • Licensing and infrastructure cost: enterprise hypervisors, management platforms and high-end hardware may be expensive.

2.3 Traditional physical servers vs virtualized servers

3. Server Virtualization

3.1 Definition

Server virtualization is the process of dividing the computing resources of one physical server into multiple virtual servers (VMs), each of which can run its own operating system and applications.

Instead of purchasing a separate physical server for every application, an organisation can run multiple virtual servers on a powerful physical host. The hypervisor manages the sharing of the underlying resources.

4. Virtualization for x86 Architecture

RED Highest-priority area: the supplied primary MCA Semester IV paper directly asks about the number of x86 virtualization techniques and asks a 15-mark question combining x86 virtualization with a virtualized data center.

4.1 What is x86 architecture?

x86 is a family of processor instruction-set architectures that originated with Intel's 8086 processor. Modern desktop and server processors commonly use the 32-bit IA-32 or 64-bit x86-64 (also called x64 or AMD64) forms. The architecture defines how software instructions interact with the processor and its execution modes.

4.2 Why did x86 virtualization need special techniques?

Traditional x86 processors were designed mainly for one operating system to control the machine. The operating system kernel executes privileged instructions and manages memory and devices. When several guest operating systems are run on one physical processor, the hypervisor must safely control privileged operations while making each guest believe it has its own computer.

In the classic x86 protection model, privilege levels are called rings. Ring 0 is the most privileged level and is traditionally used by the OS kernel; Ring 3 is used by ordinary applications. Rings 1 and 2 exist in the architecture but are rarely used by mainstream operating systems.

Figure 3: Simplified x86 privilege-ring model. This explains the privilege problem; it is not a complete diagram of modern hardware-assisted virtualization.

4.3 Three commonly taught x86 virtualization techniques

For this unit, the three commonly taught techniques are full virtualization, para-virtualization and hardware-assisted virtualization.

A. Full virtualization

  • The hypervisor provides a complete virtual hardware environment to the guest operating system.
  • The guest OS can run without being modified for virtualization.
  • The hypervisor handles sensitive or privileged operations, using techniques such as binary translation or trap-and-emulate depending on the platform.
  • Advantage: good compatibility with unmodified operating systems.
  • Limitation: some workloads may experience extra overhead due to instruction handling and device emulation.

B. Para-virtualization

  • The guest operating system is modified or otherwise made aware that it is running in a virtual environment.
  • For certain privileged operations, the guest makes explicit calls to the hypervisor. These are called hypercalls.
  • Advantage: cooperation can reduce the overhead associated with emulating certain operations.
  • Limitation: guest OS support or modification is required; this can reduce compatibility.

C. Hardware-assisted virtualization

  • The processor provides special virtualization extensions, such as Intel VT-x and AMD-V.
  • These extensions provide processor support for switching between hypervisor and guest execution contexts.
  • The guest OS can run with its expected kernel privilege inside a controlled guest mode, while the hypervisor retains control over the physical machine.
  • Advantage: improves support for unmodified guest operating systems and reduces the need for some software techniques.
  • Limitation: compatible processor, firmware settings and hypervisor support are required; hardware assistance does not remove all virtualization overhead.

Exam memory line: Full = virtual hardware; Para = guest cooperates; Hardware-assisted = CPU helps. If asked “How many commonly taught x86 virtualization techniques are there?”, answer three and name all three.

4.5 Binary translation and trap-and-emulate

These are mechanisms that may be used in full virtualization:

  • Trap-and-emulate: when a guest performs a sensitive operation that must be controlled, execution traps to the hypervisor. The hypervisor safely handles the operation and returns control to the guest.
  • Binary translation: the virtualization layer dynamically rewrites certain guest instruction sequences into safe sequences before execution, allowing the guest OS to run without modification on platforms where direct execution is unsafe.

Do not confuse these mechanisms with the three broad technique categories above. Binary translation is a method used by some full-virtualization implementations; it is not normally listed as a fourth broad category in this three-part classification.

4.6 Hardware support: Intel VT-x and AMD-V

Intel VT-x and AMD-V add processor capabilities designed to support virtual machine execution. They allow the hypervisor to control transitions between guest execution and hypervisor control, and support safer handling of privileged operations. Memory virtualisation extensions (such as Intel EPT or AMD NPT/RVI) help translate guest memory addresses efficiently.

Practical note: On many computers, virtualization support may need to be enabled in BIOS/UEFI settings. The exact setting name varies by manufacturer.

5. Hypervisor Management Software

5.1 Meaning

Hypervisor management software is the management layer or platform used by administrators to configure, monitor and control hypervisors and their virtual machines. The hypervisor runs and isolates VMs; the management software provides convenient central administration of one or more hosts and VMs.

5.2 Main functions

  1. VM creation: create VMs from templates or installation media.
  2. Resource allocation: assign virtual CPUs, RAM, virtual disks and network adapters.
  3. Power and lifecycle control: start, stop, restart, pause, clone and delete VMs.
  4. Monitoring: view CPU, memory, storage and network utilisation, as well as alerts.
  5. Migration: move a running or stopped VM between compatible hosts when supported (for example, live migration).
  6. High availability: coordinate VM restart on another host after a host failure when the cluster is configured for it.
  7. Snapshots and templates: capture VM state for short-term rollback/testing and standardise deployment. A snapshot is not a substitute for an independent backup.
  8. Access control: define administrator roles and permissions.
  9. Network and storage configuration: connect virtual switches, datastores and storage paths to VMs.
  10. Capacity planning: identify resource pressure and plan host expansion.

5.3 Hypervisor types

Type 1 — Bare-metalType 2 — Hosted
Runs directly on the physical server hardware.Runs as an application on top of a host operating system.
Common in data centers and production server environments.Common on personal computers for learning, testing and development.
Fewer software layers between hypervisor and hardware; generally efficient for server workloads.Hardware access passes through the host OS, adding another software layer.
Examples: VMware ESXi, Microsoft Hyper-V (architecture-specific), Xen; KVM is commonly deployed as a type-1-style hypervisor integrated with Linux.Examples: Oracle VirtualBox, VMware Workstation.

Figure 4: Type 1 has no general-purpose host OS layer underneath the hypervisor; Type 2 runs above a host OS.

5.4 Examples of management platforms

  • VMware vCenter Server: central management for VMware vSphere environments.
  • Microsoft Windows Admin Center / Hyper-V Manager / System Center Virtual Machine Manager: tools used to manage Hyper-V hosts and virtual machines, depending on deployment.
  • Proxmox VE: web-based management platform for KVM virtual machines and Linux containers.
  • IBM Hardware Management Console (HMC): manages IBM Power Systems partitions and related PowerVM resources.

Remember: The hypervisor performs the core virtualization work. A management platform helps administrators control the hypervisor environment at scale.

6. Logical Partitioning (LPAR)

6.1 Definition

Logical Partitioning (LPAR) is a technology that divides one physical server into multiple independent logical partitions. Each partition behaves like a separate logical computer and can run its own operating system and applications using the processor, memory and I/O resources assigned to it.

LPAR is strongly associated with IBM Power Systems and PowerVM. A partition is not necessarily a separate physical server; it is a logically separated environment created from shared hardware.

6.2 How LPAR works

  1. A physical Power server contains processors, memory and I/O devices.
  2. The Power Hypervisor (firmware layer) creates and maintains logical partitions.
  3. The administrator assigns processor capacity, memory and I/O resources to each partition.
  4. Each LPAR boots its own supported operating system, such as AIX, IBM i or Linux.
  5. Partitions operate independently while the hypervisor controls access to the underlying physical resources.

Figure 5: Logical partitioning on an IBM Power server. Exact operating systems and resource assignments depend on the model and configuration.

6.3 Types of resource assignment

  • Dedicated resources: a processor or I/O resource is assigned exclusively to a partition.
  • Shared processor capacity: processor capacity is drawn from a shared pool and scheduled among eligible partitions.
  • Dynamic LPAR (DLPAR): supported resources, such as processors, memory or I/O, can be added to or removed from a running partition under supported conditions.

6.4 Benefits of LPAR

  • Runs multiple independent operating-system environments on one physical server.
  • Improves utilisation and server consolidation.
  • Separates workloads for administration, testing and security boundaries.
  • Allows flexible resource allocation, including supported dynamic changes.
  • Can reduce data-center space, power and hardware requirements.

6.5 LPAR vs ordinary VM — useful distinction

Both provide isolated logical computing environments. LPAR is IBM Power's logical partitioning technology, managed by the Power Hypervisor/PowerVM. A conventional VM is a virtual machine created by a hypervisor platform such as VMware ESXi, Hyper-V or KVM. The precise implementation, hardware integration and resource controls differ by platform.

7. VIO Server (VIOS)

7.1 Definition

Virtual I/O Server (VIOS) is an IBM PowerVM component that runs inside a dedicated logical partition and allows client logical partitions to share physical I/O resources—such as storage and network adapters—through virtual devices.

In simple terms, VIOS acts as an I/O sharing layer. Instead of giving every client LPAR its own physical adapter, the system can connect client partitions to virtual adapters that are backed by physical devices managed by VIOS.

7.2 VIOS architecture

Figure 6: Conceptual VIOS arrangement. Client LPARs use virtual adapters; VIOS connects those virtual devices to physical I/O resources.

7.3 Main functions of VIOS

  • Virtual SCSI: presents storage to client partitions through virtual SCSI adapters.
  • Shared Ethernet Adapter (SEA): allows client partitions to communicate with external networks using physical network adapters assigned to VIOS.
  • Virtual Fibre Channel: provides virtual Fibre Channel connectivity to storage networks when supported and configured.
  • Resource sharing: allows multiple client LPARs to use shared physical I/O devices.
  • Reduced adapter requirement: can reduce the number of physical I/O adapters needed for a group of partitions.

7.4 Advantages and limitations

AdvantagesPoints to plan carefully
Improves utilisation of physical I/O adapters.VIOS becomes an important shared dependency for client I/O.
Can reduce hardware and cabling requirements.Failure or misconfiguration can affect multiple client partitions.
Provides flexible virtual storage and network connectivity.Needs correct redundancy, backups, patching and monitoring.
Can simplify the I/O layout of a Power server.Performance depends on adapter capacity and configuration.

Do not confuse: VIOS is not a general-purpose cloud operating system and is not the same as a hypervisor. It is a specialised IBM Power partition that provides virtual I/O services to other partitions.

8. Virtual Infrastructure Requirements

8.1 What is a virtual infrastructure?

A virtual infrastructure is the complete set of physical hardware, virtualization software, virtual machines, storage, networking, security and management tools required to operate a virtualized IT environment.

8.2 Main requirements

RequirementWhat is needed and why
1. Compute hardwareCompatible CPUs with sufficient cores, memory capacity and hardware virtualization support (for example Intel VT-x or AMD-V where required).
2. Hypervisor platformA supported hypervisor to create, run, isolate and manage VMs.
3. Memory (RAM)Enough physical RAM for the host and its VMs, with allowance for peaks and overhead.
4. StorageReliable disks or shared storage with adequate capacity, IOPS, throughput, backup and recovery.
5. NetworkPhysical NICs, switches, VLANs or virtual networks, sufficient bandwidth and redundant paths.
6. Management toolsTools for provisioning, monitoring, migration, access control, patching and capacity management.
7. SecurityStrong administrator authentication, role-based access, patching, secure configuration, network segmentation and logging.
8. Availability and backupRedundant power, cooling, network and storage paths; tested backups and disaster recovery procedures.
9. Facility and powerSuitable rack space, electricity, cooling, fire protection and physical security for on-premises systems.
10. Skills and processesTrained administrators, documentation, change control, monitoring and incident response.

8.3 Capacity planning — do not simply count VMs

A server's ability to host VMs depends on the resources each workload needs. An administrator should estimate average and peak CPU use, RAM, storage capacity, storage performance, network throughput and expected growth. Overcommitting resources can improve utilisation, but excessive overcommitment can cause performance problems.

8.4 Simple planning example

A small organisation wants to run a web server, database server and development server. It should first estimate the CPU, memory, disk and network needs of all three workloads. It then selects a compatible host and hypervisor, plans separate virtual networks where appropriate, provides reliable storage and backup, and configures monitoring and administrator access. Only after checking total capacity should it decide how many VMs can safely run on the host.

9. Storage Virtualization

9.1 Definition

Storage virtualization is the process of combining or abstracting storage capacity from multiple physical storage devices and presenting it to servers or applications as logical storage resources.

Instead of requiring an administrator to manage every physical disk separately, storage virtualization creates a logical view—such as a virtual volume, pool or datastore—that can be allocated to workloads.

9.2 How it works

  1. Multiple physical storage devices are connected to a storage system or network.
  2. Storage virtualization software or a storage controller abstracts the physical devices.
  3. The devices may be combined into logical pools.
  4. The administrator creates logical volumes or file shares from those pools.
  5. Servers and VMs access the logical storage without needing to manage the physical disk layout directly.
  6. The storage system maps logical requests to the appropriate physical locations.

Figure 7: Storage virtualization hides the complexity of physical devices and presents logical storage to servers.

9.3 Benefits

  • Centralised storage administration.
  • Better utilisation by pooling unused capacity.
  • Flexible allocation and expansion of logical volumes.
  • Can support data migration between physical devices with less disruption, depending on the platform.
  • Can simplify snapshots, replication, tiering and backup integration.
  • Can improve availability when redundancy and replication are properly designed.

9.4 Common forms of storage virtualization

  • Block-level virtualization: physical storage blocks are abstracted and presented as logical block devices or volumes. Common in SAN environments.
  • File-level virtualization: abstracts the location of files and presents a unified namespace or file access layer. Common in NAS environments.
  • Object storage abstraction: data is managed as objects with identifiers and metadata, usually accessed through APIs. This is common in cloud object storage, although object storage is not simply another name for SAN or NAS.

10. Storage Area Network (SAN)

10.1 Definition

A Storage Area Network (SAN) is a dedicated high-speed network that connects servers to shared storage systems and presents storage to servers primarily as block devices, similar to locally attached disks.

10.2 Main components

  • Hosts / servers: systems that need access to shared storage.
  • Host Bus Adapter (HBA): interface in a server used to connect to a storage network, commonly Fibre Channel.
  • SAN switches / fabric: connect hosts and storage arrays and carry storage traffic.
  • Storage arrays: systems containing disks or flash storage and controllers.
  • Logical Unit Number (LUN): an addressable logical storage unit presented to a host.
  • Multipathing: multiple physical paths between a server and storage to improve availability and sometimes performance.

10.3 How SAN works

  1. An administrator creates a logical volume or LUN on the storage array.
  2. The storage network connects the server to the storage system through switches and adapters.
  3. Access controls (such as zoning and LUN masking) determine which hosts can access the storage.
  4. The server discovers the LUN and uses it as a block device, often formatting it with a file system or using it for a database.
  5. Read and write requests travel over the SAN fabric to the storage array.

Figure 8: Simplified SAN layout. Real SANs commonly use redundant switches and multiple paths.

10.4 Common SAN protocols

  • Fibre Channel (FC): a high-speed networking technology designed for storage traffic.
  • iSCSI: carries SCSI storage commands over IP networks, commonly Ethernet.
  • Fibre Channel over Ethernet (FCoE): carries Fibre Channel frames over Ethernet in supported environments.

10.5 Advantages and limitations

  • Advantages: high performance, centralised block storage, scalability, shared access for server clusters, and support for redundant paths.
  • Limitations: higher cost, specialised skills, more complex design and administration, and careful zoning/access configuration.

11. Network-Attached Storage (NAS)

11.1 Definition

Network-Attached Storage (NAS) is a dedicated file-storage system connected to a network. It allows authorised users and computers to store, retrieve and share files from a central location.

Think of NAS as a shared network drive for a team or organisation. Users work with folders and files rather than managing raw disk blocks.

11.2 How NAS works

  1. A NAS device or NAS server is connected to an Ethernet network.
  2. The administrator creates shared folders and configures users and permissions.
  3. A client connects to the NAS using a file-sharing protocol.
  4. The user reads, creates, modifies or deletes files according to the permissions granted.
  5. The NAS system manages the underlying disks and file system.

11.3 Common NAS protocols

  • NFS (Network File System): widely used for file sharing in Unix and Linux environments.
  • SMB (Server Message Block): widely used for file and printer sharing, especially in Windows environments.

11.4 Advantages and limitations

  • Advantages: easy file sharing, centralised management, simpler deployment than many SAN designs, user-level permissions and convenient access from multiple devices.
  • Limitations: performance depends on network capacity and NAS design; it may not be ideal for every high-IOPS database workload; scale and redundancy depend on the appliance or cluster architecture.

12. Cloud Server Virtualization

12.1 Meaning

Cloud server virtualization is the use of virtualization technology in a cloud environment to create and operate virtual server instances from shared physical server infrastructure. A cloud provider pools physical servers and uses hypervisors or other virtualization technologies to allocate isolated compute environments to customers.

A customer can request a virtual server with a chosen operating system, CPU, memory, storage and network configuration without buying the physical machine.

12.2 How it works

  1. The cloud provider operates physical servers in data centers.
  2. A hypervisor or virtualization platform abstracts the physical hardware.
  3. The cloud control plane receives a request for a virtual server (instance).
  4. The platform selects a suitable host and allocates virtual CPU, memory, storage and networking.
  5. The instance boots an operating system image and becomes available to the customer.
  6. The customer installs applications, manages the guest OS where permitted, and pays according to the provider's pricing and metering model.
  7. The provider monitors the physical infrastructure and maintains the underlying platform; responsibility boundaries depend on the service model.

Figure 9: Conceptual cloud server virtualization. A provider's control plane provisions instances onto a shared physical host pool.

12.3 Benefits

  • On-demand provisioning: virtual servers can be created when required.
  • Elasticity: compute capacity can be increased or decreased according to workload and service limits.
  • Resource pooling: many customers and workloads share a large physical resource pool with logical isolation.
  • Cost model: customers can avoid purchasing and maintaining their own physical servers and may pay for measured usage.
  • Faster deployment: standard images and automation speed up server creation.
  • Geographic options: providers may offer deployment in multiple regions and availability zones.

12.4 VM vs cloud server instance

A cloud server instance is generally a VM or VM-like compute resource delivered as a managed cloud service. The important difference is not the basic virtual machine concept; it is the surrounding cloud service: self-service provisioning, APIs, resource pools, metering, networking options and provider-operated infrastructure.

12.5 Security and responsibility

Virtualization provides isolation, but it does not automatically make a system secure. Hypervisors must be patched and protected, VM images must be trusted, management interfaces must be access-controlled, and virtual networks must be segmented. In IaaS, the provider generally protects the physical infrastructure and virtualization layer while the customer remains responsible for many guest OS, application, identity and data configurations. Exact responsibility depends on the service and provider.

13. Virtualized Data Center

RED Direct 15-mark focus: “What is Virtualized Data Center? Explain virtualization in x86 architecture.” appears in the supplied primary MCA Semester IV 2022–24 paper. Prepare the definition, architecture, working and benefits clearly.

13.1 Definition

A virtualized data center is a data-center environment in which physical computing, storage and networking resources are abstracted into logical or virtual resources and centrally managed through virtualization software.

Instead of managing every workload as a separate physical server, the organisation operates pools of compute, storage and network capacity. Virtual machines and applications use these logical resources as needed.

13.2 Main components

  • Compute virtualization: physical servers and CPUs are abstracted into virtual machines or compute instances.
  • Storage virtualization: physical disks and arrays are pooled and presented as logical volumes, datastores or file/object services.
  • Network virtualization: virtual switches, VLANs, virtual networks, routers and firewalls connect and isolate workloads.
  • Hypervisor layer: creates and runs VMs on physical hosts.
  • Management and orchestration: central tools automate provisioning, monitoring, migration and resource allocation.
  • Security: identity and access control, segmentation, patching, logging and protection of management systems.
  • Facilities: physical data center, power, cooling, racks and connectivity.

13.3 Architecture of a virtualized data center

Figure 10: Conceptual virtualized data center. The compute, storage and network layers are virtualized and centrally managed over physical infrastructure.

13.4 How it works

  1. Physical servers, storage arrays and network devices are installed in the data center.
  2. Hypervisors are deployed on compute hosts to create virtual machines.
  3. Storage systems are pooled and presented to hosts as logical storage.
  4. Virtual switches and network policies connect VMs and separate traffic.
  5. Management software provides a central view and automates VM provisioning, monitoring and migration.
  6. Security, backup, replication and availability controls protect the workloads and infrastructure.
  7. Administrators monitor utilisation and add or redistribute resources as demand changes.

13.5 Benefits

  • Consolidates physical servers and improves resource utilisation.
  • Reduces hardware, power, cooling and floor-space requirements when properly planned.
  • Provides flexible and faster provisioning of compute, storage and network resources.
  • Supports centralised monitoring and automation.
  • Can improve availability and disaster recovery through clustering, replication and VM migration.
  • Enables workload isolation and supports multiple operating systems.
  • Can make infrastructure expansion more modular and manageable.

13.6 Challenges

  • Initial investment and licensing costs can be high.
  • Management and troubleshooting require specialist skills.
  • Resource contention and overcommitment can affect performance.
  • A failure in shared infrastructure may affect many workloads.
  • Misconfiguration or compromise of central management and hypervisor layers can have a broad impact.
  • Backup, network segmentation, monitoring and disaster recovery need careful design.

13.7 Virtualized data center vs traditional data center

Traditional data centerVirtualized data center
More workloads tied to individual physical servers.Workloads run on virtual resources pooled across hosts.
Provisioning often requires physical installation and configuration.Many resources can be provisioned through software and automation.
Compute, storage and network may be managed in separate silos.Virtual resource pools can be centrally coordinated.
Hardware utilisation may be lower if servers are dedicated to small workloads.Resource sharing can improve utilisation, subject to capacity planning.
Workload movement may require physical migration.VM migration and replication can support workload mobility where supported.

14.4 Common confusions — clear them before the exam

  • VM vs hypervisor: the VM is the virtual computer; the hypervisor creates and manages it.
  • Host vs guest: host is the physical machine; guest OS runs inside a VM.
  • Full vs para-virtualization: full virtualization generally supports an unmodified guest; para-virtualization requires guest cooperation.
  • Hypervisor vs management software: the hypervisor runs VMs; management software administers hosts and VMs centrally.
  • LPAR vs VIOS: LPAR is a logical partition; VIOS is a specialised partition that provides virtual I/O to client partitions.
  • SAN vs NAS: SAN primarily presents block storage; NAS provides file-level access.
  • Snapshot vs backup: a snapshot captures a point-in-time VM or disk state; a proper backup should be independently protected and recoverable.
  • Virtualization vs cloud computing: virtualization is a technology that abstracts resources; cloud computing adds service delivery, self-service, resource pooling, elasticity and measured usage.

14.5 Diagram practice checklist

  • Basic virtualization stack: VMs → hypervisor → physical hardware.
  • x86 privilege rings: Ring 0 kernel, Ring 3 applications, Rings 1 and 2 rarely used.
  • Type 1 vs Type 2 hypervisor stack.
  • LPAR architecture: physical Power server → Power Hypervisor → independent partitions.
  • VIOS architecture: client LPARs → VIOS → physical storage/network adapters.
  • Storage virtualization: physical arrays → virtualization layer → logical volumes.
  • SAN and NAS comparison diagrams.
  • Virtualized data center: applications/VMs → virtual compute, network and storage → management/security → physical foundation.
