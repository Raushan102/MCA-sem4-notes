1. Cloud Ecosystem RED

WHY STUDY THIS TOPIC

It has direct previous-year relevance. A 15-mark question and a 1-mark question on it are confirmed in the primary Ranchi University MCA Semester IV paper (2022–24), and more questions are in the compiled question collection.

HOW MUCH DEPTH: detailed preparation. Be ready for 1-mark, 5-mark and 15-mark answers.

1.1 What is a Cloud Ecosystem?

A Cloud Ecosystem is a collection of different participants, technologies, services and infrastructure that work together to provide and use cloud computing services.

In simple words, cloud computing does not work through one company or one technology alone. Different organisations and components work together to deliver cloud services to users.

Example: when you store a file in Google Drive:

  • Google provides the cloud storage service.
  • You act as the cloud consumer.
  • Internet connectivity helps you access the service.
  • Data centres and servers store your files.
  • Security mechanisms protect your account and data.
  • Other service partners may support billing, auditing or management.

All these participants and components together form a cloud ecosystem.

1.2 Main components: the five actors

The cloud ecosystem includes five major participants. These five actors are defined in the NIST Cloud Computing Reference Architecture.

  1. Cloud Consumer
  2. Cloud Service Provider
  3. Cloud Broker
  4. Cloud Auditor
  5. Cloud Carrier

Figure 1.1: The five actors of the cloud ecosystem (simplified from the NIST reference architecture).

REMEMBER: this is the diagram to practise for your 15-mark answer. It is a simplified study diagram. It does not show every communication path.

1.3 The five actors in detail

A. Cloud Consumer

A Cloud Consumer is a person or organisation that uses cloud services provided by a Cloud Service Provider.

Example: a student using Google Drive to store notes, or a company using AWS to host its website.

Main responsibilities:

  • Select suitable cloud services.
  • Use cloud resources.
  • Manage user accounts and access.
  • Pay for services according to the agreement.
  • Follow the provider's usage and security policies.

B. Cloud Service Provider (CSP)

A Cloud Service Provider is an organisation that makes cloud services available to consumers over a network.

Examples: Amazon Web Services (AWS), Microsoft Azure, Google Cloud.

A CSP provides three major service models: IaaS (Infrastructure as a Service), PaaS (Platform as a Service) and SaaS (Software as a Service).

Main responsibilities:

  • Provide cloud infrastructure.
  • Manage servers, storage and networking.
  • Provide cloud applications and platforms.
  • Maintain service availability.
  • Implement security controls.
  • Monitor and manage cloud resources.

C. Cloud Broker

A Cloud Broker acts as an intermediary between cloud consumers and cloud service providers. It helps consumers select, combine and manage cloud services from different providers.

Example: a company wants to use AWS for computing and Microsoft Azure for another service. A cloud broker can help coordinate and manage these services.

Three important functions of a Cloud Broker:

  1. Service Intermediation: adds extra value to an existing cloud service, such as identity management or security monitoring.
  2. Service Aggregation: combines multiple cloud services into one integrated solution.
  3. Service Arbitrage: selects services dynamically from different providers based on price, performance or requirements.

Figure 1.2: What a cloud broker does between a consumer and several providers.

D. Cloud Auditor

A Cloud Auditor is an independent person or organisation that examines cloud services and operations. Its purpose is to check whether cloud services follow required security, privacy and performance standards.

Main responsibilities:

  • Conduct security audits.
  • Check privacy protection.
  • Evaluate service performance.
  • Check compliance with standards and agreements.

Example: an independent auditor examines whether a cloud provider follows the required security controls.

E. Cloud Carrier

A Cloud Carrier provides the network connectivity and transport through which cloud services are delivered from the provider to the consumer. In simple words, it provides the communication path between the cloud provider and the user.

Example: an internet service provider or telecom operator that connects your computer to AWS or Google Cloud.

Main responsibilities:

  • Provide network connectivity.
  • Transfer data between consumers and providers.
  • Maintain network availability.
  • Support reliable communication.

1.4 How does the Cloud Ecosystem work?

Consider a company that wants to host its website using AWS.

  1. The company acts as the Cloud Consumer.
  2. AWS acts as the Cloud Service Provider.
  3. The company may use a Cloud Broker to compare and manage cloud services.
  4. A Cloud Auditor may independently check security and compliance.
  5. A Cloud Carrier provides the network connection between the company and AWS.
  6. AWS uses servers, storage, networking and data centres to deliver the requested services.

Figure 1.3: A company hosts its website on AWS. Every actor has a part to play.

Thus, all these actors work together to provide cloud computing services.

1.7 Role of a Cloud Service Provider in the ecosystem

The Cloud Service Provider is one of the most important actors because it delivers cloud services to consumers. Its major functions:

  1. Infrastructure Management: manages physical servers, storage and networking.
  2. Service Delivery: provides IaaS, PaaS and SaaS.
  3. Resource Management: allocates computing resources according to customer requirements.
  4. Security Management: protects infrastructure, applications and customer data.
  5. Service Monitoring: monitors performance and availability.
  6. Billing and Metering: measures resource usage and charges customers.
  7. Customer Support: helps customers resolve technical problems.

1.8 Advantages of a Cloud Ecosystem

  1. Resource Sharing: different users can access shared cloud infrastructure.
  2. Scalability: resources can increase or decrease according to demand.
  3. Cost Efficiency: organisations can reduce the need to purchase and maintain physical infrastructure.
  4. Flexibility: consumers can choose different cloud services.
  5. Better Collaboration: different participants can work together to deliver services.
  6. Security and Auditing: auditors and providers help assess and improve security.
  7. Easy Access: cloud services can be accessed through network connections.

2. Cloud Business Process Management RED

WHY STUDY THIS TOPIC

It appeared as a 15-mark question in the primary Ranchi University MCA Semester IV paper (2022–24, ECMCA-401C).

HOW MUCH DEPTH: detailed preparation. Learn the 15-mark answer well, and be ready for the two 1-mark questions from the compiled collection.

2.1 First understand: what is a business process?

A business process is a sequence of related tasks or activities performed by an organisation to achieve a specific goal.

Example: when a customer purchases a product online, the business follows a process:

  1. Customer places an order.
  2. Payment is checked.
  3. Product availability is checked.
  4. Product is packed.
  5. Product is shipped.
  6. Customer receives a delivery notification.

All these connected activities form an order-processing business process.

Other examples of business processes: employee recruitment, customer registration, bank loan approval, hospital appointment booking, invoice generation and payment.

2.2 What is BPM?

BPM stands for Business Process Management. It is a systematic approach used to design, execute, monitor, analyse and improve business processes. In simple words, BPM helps an organisation manage its work in an organised and efficient way.

Example: a bank loan approval process.

  • A customer submits a loan application.
  • The bank verifies the documents.
  • The credit department checks the customer's eligibility.
  • The manager approves or rejects the loan.
  • The customer receives the final decision.

BPM helps organise and manage these steps so that the work is completed properly and efficiently.

Main activities of BPM

  1. Process Design: plan how the business process should work.
  2. Process Execution: perform the planned activities.
  3. Process Monitoring: track the progress of activities.
  4. Process Analysis: identify delays, errors and bottlenecks.
  5. Process Improvement: make changes to improve performance.

Figure 2.1: The five main activities of BPM. Improvement feeds back into design.

2.3 What is Cloud BPM?

Cloud BPM (Cloud Business Process Management) is the use of cloud-based software and services to design, execute, monitor and improve business processes.

In traditional BPM, an organisation may need to install and maintain BPM software on its own servers. In Cloud BPM, the BPM software is hosted on cloud infrastructure and accessed through the internet or a network.

Example: a company uses a cloud-based workflow system to manage employee leave applications.

  • Employee submits a leave request.
  • The system sends it to the manager.
  • The manager approves or rejects it.
  • The system updates the leave record.
  • The employee receives a notification.

The company does not necessarily need to maintain its own BPM servers.

Figure 2.2: Traditional BPM and Cloud BPM. The software is the same idea; where it runs is different.

2.5 Main components of Cloud BPM

  1. Process Modelling and Design: creates a visual representation of a business process and defines the order of tasks and decision points. Example: designing a loan approval workflow.
  2. Workflow Engine: executes the designed workflow, assigns tasks to the appropriate people or departments, and moves the process from one step to another.
  3. Process Integration: connects the BPM system with other applications. Example: connecting an order system with a payment gateway and inventory database.
  4. Process Monitoring: tracks the progress of business processes and shows pending, completed and delayed tasks.
  5. Process Analytics: analyses process performance and helps identify bottlenecks and inefficiencies.
  6. Security and User Management: controls who can access or perform particular tasks. Supports authentication, permissions and access control.

2.6 How does Cloud BPM work?

Example: online order processing in an e-commerce company.

  1. Order received: the customer places an order through the website.
  2. Payment verification: the BPM workflow sends the payment request for verification.
  3. Inventory checking: the system checks whether the product is available.
  4. Packing and shipping: the workflow assigns tasks to the warehouse and delivery team.
  5. Customer notification: the customer receives an order and delivery update.
  6. Monitoring and improvement: the company checks processing time, delays and errors.

Figure 2.3: Cloud BPM workflow for an online order. The software coordinates all six steps.

The cloud BPM software coordinates these activities and helps the organisation track the entire process.

2.7 Why is Cloud BPM software needed?

IMPORTANT: this is the most important part of the 15-mark question.

  1. Reduced infrastructure cost: an organisation may not need to purchase and maintain its own servers for BPM software. This can reduce initial infrastructure investment.
  2. Accessibility: employees and managers can access the BPM system from different locations through an authorised network connection.
  3. Scalability: when the organisation grows or the number of business processes increases, cloud resources can generally be scaled according to demand.
  4. Better collaboration: employees, managers and different departments can work together on the same business process.
  5. Process automation: repeated manual tasks, such as sending approval requests and notifications, can be automated.
  6. Real-time monitoring: managers can track process progress, pending tasks, delays and performance.
  7. Easy integration: Cloud BPM can connect with other business applications, such as databases, payment systems, CRM and ERP software.
  8. Faster deployment: cloud-based BPM environments can be made available without first building and maintaining all the supporting IT infrastructure. IBM describes its BPM-on-cloud offering as a PaaS environment for developing, testing, running and monitoring processes.
  9. Improved productivity: automation reduces repetitive work and allows employees to focus on more important activities.
  10. Continuous improvement: by analysing process performance, organisations can identify bottlenecks and improve their workflows.

3. Cloud Service Management YELLOW

WHY STUDY THIS TOPIC

The questions below are listed in the compiled question collection. They are not confirmed as questions from the primary 2022–24 MCA Semester IV paper, so treat this as a YELLOW topic and not a confirmed RED question.

HOW MUCH DEPTH: study the concepts and prepare a 5-mark answer.

3.1 What is Cloud Service Management?

First understand the two words:

  • Cloud Service: a service delivered through cloud computing, such as virtual machines, cloud storage, databases or online software.
  • Management: controlling, monitoring and maintaining something so that it works properly.

Cloud Service Management (CSM) refers to all the functions needed to manage and operate cloud services that are provided to cloud consumers.

In simple words: Cloud Service Management means managing cloud services throughout their operation so that customers receive the services they require with the expected quality.

Example: a company uses AWS to host its website. Someone must manage customer accounts, service contracts, resource provisioning, performance monitoring, usage measurement, billing and service availability. These activities come under Cloud Service Management.

The NIST Cloud Computing Reference Architecture describes three major perspectives of Cloud Service Management: Business Support, Provisioning and Configuration, and Portability and Interoperability.

3.2 Three major components of Cloud Service Management

IMPORTANT: this is the most important concept in this topic.

Figure 3.1: The three components of Cloud Service Management (simplified from the NIST reference architecture).

A. Business Support

Business-related activities required to manage customers and support cloud service operations.

  1. Customer Management: manages customer accounts and profiles, handles customer relationships and resolves customer problems and queries. Example: creating and managing an AWS customer account.
  2. Contract Management: manages agreements between cloud providers and customers, including contract creation, negotiation and termination. Example: managing a customer's cloud service agreement.
  3. Inventory Management: maintains information about available cloud services and manages the service catalogue. Example: a list of available virtual machines, databases and storage services.
  4. Accounting and Billing: records customer usage, calculates service charges, generates invoices and manages payments. Example: calculating monthly charges based on virtual machine usage.
  5. Reporting and Auditing: generates reports about service usage and customer activities, and helps examine service operations and maintain records.

B. Provisioning and Configuration

Manages the creation, configuration and operation of cloud services and resources.

  1. Rapid Provisioning: quickly provides cloud resources according to customer requirements. Example: creating a virtual machine when a customer requests one.
  2. Resource Change: allows resources to be modified when requirements change. Example: increasing a virtual machine's memory or CPU capacity.
  3. Monitoring and Reporting: tracks the condition and performance of cloud services. Example: monitoring CPU usage and service availability.
  4. Metering: measures how much of a cloud service a customer uses. Example: storage consumption in GB or virtual machine running time.
  5. SLA Management: monitors whether the cloud provider meets the service commitments agreed with the customer. Example: checking whether the service meets its agreed availability target.

C. Portability and Interoperability

These functions help customers move data, applications and services between different cloud environments and work with different systems.

  1. Data Portability: move data from one cloud environment to another. Example: moving files from one cloud storage provider to another.
  2. Copy Data To-From: copy data between cloud systems or between a cloud and another environment.
  3. Bulk Data Transfer: transfer large amounts of data efficiently.
  4. Service Interoperability: different cloud services and systems communicate and work together. Example: connecting a cloud application to a cloud database.
  5. Unified Management Interface: a common interface for managing different cloud services.
  6. System Portability: move systems or workloads between environments.
  7. VM Image Migration: move virtual machine images between supported environments.
  8. Application/Service Migration: transfer applications or services to another cloud environment.

These functions are particularly useful when an organisation wants flexibility and does not want to become unnecessarily dependent on one cloud provider.

3.3 How Cloud Service Management works

Example: a company wants to create a virtual machine on a cloud platform.

  1. Customer request: the company requests a virtual machine with specific CPU, memory and storage.
  2. Business support: the provider manages the customer account, service agreement and billing details.
  3. Provisioning and configuration: the provider creates and configures the virtual machine.
  4. Monitoring and SLA management: the provider monitors the service and checks whether it meets the agreed service levels.
  5. Usage measurement and billing: the provider measures resource usage and calculates the charges.
  6. Portability: if required and technically supported, the customer can move data or workloads to another environment.

Figure 3.2: Cloud Service Management from the first request to ongoing operation.

This shows how Cloud Service Management supports a cloud service from the customer's request through its ongoing operation.

3.4 Cloud Service Management vs Resource Management

These two terms are related, but they are not exactly the same.

4.1 What is Cloud Stack?

A Cloud Stack is a collection of technology layers and components that work together to provide cloud computing services.

In simple words, a cloud stack describes how cloud services are organised, from the physical hardware at the bottom to the applications used by customers at the top.

Example: when you use Google Drive:

  • Physical servers store your files.
  • Virtualisation helps share computing resources.
  • Cloud infrastructure provides storage and networking.
  • The platform supports the application.
  • Google Drive provides the software interface you use.

These layers work together as a cloud stack.

4.2 Layers of the Cloud Stack

Figure 4.1: The layers of a simplified cloud stack. The NIST view groups them into three layers (right).

NOTE: this is a simplified teaching diagram. Actual cloud-provider architectures can combine or separate layers differently. The NIST reference architecture describes a provider stack using three main layers: Service Layer, Resource Abstraction and Control Layer, and Physical Resource Layer. The service layer contains SaaS, PaaS and IaaS.

1. Physical Resource Layer

The bottom layer. It contains the actual physical resources required to run cloud services: physical servers, storage devices, network equipment, data centres, and power and cooling facilities.

2. Virtualisation Layer

Creates virtual versions of physical resources: virtual machines, virtual storage, virtual networks and hypervisors. It helps multiple customers share physical resources while maintaining logical separation.

3. Infrastructure Layer (IaaS)

IaaS stands for Infrastructure as a Service. It provides computing infrastructure through cloud services: virtual servers, cloud storage, virtual networks and computing resources. Example: Amazon EC2.

4. Platform Layer (PaaS)

PaaS stands for Platform as a Service. It provides a platform where developers can build, test and deploy applications without managing all the underlying infrastructure: application runtime environments, development tools, managed databases and middleware.

5. Application Layer (SaaS)

SaaS stands for Software as a Service. It provides ready-to-use software applications over a network. Examples: Gmail, Google Drive, Microsoft 365, Salesforce.

4.3 How do the layers work together?

Example: a developer wants to deploy a website.

  1. The physical layer provides servers, storage and networking.
  2. The virtualisation layer creates virtual machines.
  3. The infrastructure layer provides computing resources.
  4. The platform layer provides the runtime and development environment.
  5. The application layer delivers the website to users.

This is how different layers cooperate to deliver a cloud application.

4.4 Difference between IaaS, PaaS and SaaS

ModelWhat it providesExample

PaaSApplication development platformGoogle App Engine
SaaSReady-to-use softwareGmail

REMEMBER: IaaS provides infrastructure, PaaS provides a platform, and SaaS provides software.

4.5 Why is Cloud Stack important?

  • Organisation: divides cloud technology into manageable layers.
  • Resource utilisation: helps share and use physical resources efficiently.
  • Scalability: makes it easier to expand cloud resources.
  • Flexibility: different layers can be managed or updated independently.
  • Service delivery: helps providers deliver different types of cloud services.

5.1 What is Computing on Demand?

Computing on Demand (COD) means getting computing resources whenever they are needed, instead of buying and maintaining all the resources permanently.

These resources can include:

  • Computing power: CPU and RAM.
  • Storage: space to store files and databases.
  • Networking: network bandwidth and connectivity.
  • Software: applications and development platforms.

The user requests resources when required, uses them, and can release them when they are no longer needed. Depending on the service, charges may be based on actual usage or a subscription plan.

Simple example: you run an online shopping website.

  • On normal days, 2 servers are enough.
  • During a festival sale, thousands of customers visit your website.
  • You temporarily increase the number of servers to handle the traffic.
  • After the sale, you reduce the servers again.

This is an example of on-demand computing.

Figure 5.2: On-demand capacity follows traffic. The server counts are example numbers.

5.2 How does Computing on Demand work?

  1. User requests resources. Example: request a virtual machine with 4 CPUs and 8 GB RAM.
  2. Resources are provisioned. The cloud provider allocates the requested resources.
  3. User uses the resources. Runs applications, processes data or stores files.
  4. Usage is monitored. The provider measures resource consumption.
  5. Resources are scaled or released. Resources are increased, reduced or released. Billing is calculated according to the applicable pricing model.

Figure 5.1: How Computing on Demand works.

5.4 Benefits of Computing on Demand

  1. Cost efficiency: no need to purchase expensive hardware upfront.
  2. Scalability: resources can be increased or decreased as needed.
  3. Flexibility: users can select the resources they require.
  4. Faster deployment: resources can be made available quickly.
  5. Better resource utilisation: resources can be released when no longer required.
  6. Reduced maintenance: the cloud provider manages much of the underlying infrastructure.

5.5 Challenges of Computing on Demand

  • Unexpected costs: high usage can increase the bill.
  • Internet dependency: access generally requires network connectivity.
  • Security concerns: data and applications are hosted on provider infrastructure.
  • Vendor lock-in: moving workloads between providers may be difficult.
  • Availability risks: provider outages can interrupt services.

5.7 COD and On-Demand Self-Service: are they the same?

They are related, but not exactly the same.

  • Computing on Demand: the broader idea of obtaining computing resources according to current requirements.
  • On-Demand Self-Service: a cloud characteristic in which a consumer can independently request and provision resources, usually through a portal or API, without requiring direct human interaction with the provider.

EXAMPLE: creating a virtual machine through the AWS console is an example of on-demand self-service.

6.1 What is Cloud Sourcing?

Cloud Sourcing is the process of obtaining IT resources and services, such as software, storage, computing power and infrastructure, from an external cloud service provider instead of owning and managing everything internally.

In simple words, rather than building your own data centre and buying all the hardware, you use services provided by companies like AWS, Microsoft Azure or Google Cloud.

Example: you want to launch an online shopping website. Instead of buying physical servers, building a data centre, purchasing storage devices and maintaining networking equipment, you can use AWS to rent computing resources, store data and host your website. This is an example of Cloud Sourcing.

Figure 6.2: Instead of owning every item on the left, the organisation sources services from a provider.

6.2 How does Cloud Sourcing work?

  1. Customer / Organisation needs computing resources or software.
  2. Selects a Cloud Service Provider. Example: AWS, Azure or Google Cloud.
  3. Obtains Cloud Services: IaaS, PaaS or SaaS.
  4. Uses and manages the services: monitors performance, cost and security.

6.4 Benefits of Cloud Sourcing

  1. Reduced cost: less investment in physical hardware.
  2. Scalability: resources can be increased or decreased.
  3. Flexibility: organisations can select suitable services.
  4. Faster deployment: services can be accessed quickly.
  5. Less maintenance: providers manage much of the underlying infrastructure.
  6. Access to technology: organisations can use modern cloud services without building everything themselves.

6.5 Challenges of Cloud Sourcing

  • Data security: sensitive information is stored with an external provider.
  • Vendor lock-in: switching providers can be difficult.
  • Internet dependency: services generally require network connectivity.
  • Service availability: provider outages can affect business operations.
  • Compliance: organisations must ensure that data handling follows applicable laws and regulations.
