Topic 1. Essentials of Cloud Computing

BLACKBLACK priority: one-time reading, but understand the fundamentals

WHY STUDY THIS TOPIC?

It was not directly asked in the previous papers, but it is the foundation for the rest of Unit I. Understand the basic meaning, how cloud computing works and what resources it provides.

How much depth is needed?

  • 1 mark: Define Cloud Computing; explain the term Cloud.
  • 5 marks: Explain Cloud Computing with basic working and examples; know its basic types.
  • 15 marks: Not a confirmed direct 15-mark question. Cover the fundamentals, then study benefits, need and characteristics separately.

1.1 Meaning of Cloud Computing

Cloud: the word cloud generally refers to resources and services available through a network, usually the Internet. They are hosted at remote locations, not only on your personal computer.

Computing: using computer resources to process data, store files, run applications and manage databases.

Definition

Cloud Computing is a technology that provides computing resources such as servers, storage, databases, networking and software over the Internet whenever users need them.

These resources are generally managed by a cloud service provider. Users access them remotely without buying and maintaining all the hardware themselves.

Real-life example: Google Drive

  1. You open Google Drive on your mobile phone.
  2. You upload a photo using the Internet.
  3. Google stores the photo on its remote infrastructure.
  4. Later, you open Google Drive on your laptop.
  5. You access the same photo without transferring it manually.

IMPORTANT

The cloud does not mean data is stored somewhere in the sky. Data and computing resources are hosted on remote computers, usually inside large data centres.

1.3 How does Cloud Computing work?

Traditional local computing: the user installs software and stores files on their own computer or the organization’s own servers.

Cloud computing: the user connects to a cloud provider over a network and uses resources hosted by that provider.

Basic working steps

  1. User request: a user opens a cloud application or requests a resource.
  2. Internet connection: the request travels through the Internet to the provider.
  3. Cloud infrastructure: the provider’s servers process the request or retrieve the data.
  4. Response: the result is sent back to the user’s device.
  5. Resource management: the provider manages the infrastructure; the user’s responsibilities depend on the service used.

Example: when you open Gmail, your browser sends a request to Google’s systems, which process it and return your emails.

1.4 Basic components

  1. Client or Front End: the device or interface used to access cloud services (mobile, laptop, web browser).
  2. Internet or Network: connects the user’s device to the cloud infrastructure.
  3. Cloud Infrastructure or Back End: remote servers, storage, databases and software that provide the services.

Example with Google Drive: your laptop is the client, your Internet connection carries the request, and Google’s cloud infrastructure stores and retrieves your files.

Topic 2. Benefits and Need for Cloud Computing

REDRED priority: directly asked in the MCA Semester IV previous paper (5 marks)

WHY THIS TOPIC?

It deserves more detail than Topic 1. Prepare it so you can answer a 5-mark question confidently and also expand it into a longer answer.

2.1 Why do we need Cloud Computing?

Before cloud computing, organizations generally bought and maintained their own IT infrastructure. A company launching an online shop needs physical servers, storage devices, networking equipment, software and databases, plus IT professionals to install, manage and maintain everything.

Problems with traditional computing

  1. High initial investment: servers, storage, networking equipment and software must be purchased before starting.
  2. Maintenance responsibility: IT staff must maintain hardware, install updates, monitor systems and solve problems.
  3. Difficulty handling changing demand: a website with 1,000 visitors a day may get 100,000 during a festival sale, and existing servers may not cope.
  4. Resource wastage: extra hardware bought for peak demand is wasted if unused.
  5. Limited accessibility: local infrastructure makes remote access need extra arrangements.
  6. Slow infrastructure setup: buying, installing and configuring servers takes time.

How Cloud Computing solves these problems

Organizations rent computing resources from providers instead of buying and maintaining all the hardware.

  • Start with the resources you need.
  • Increase or decrease resources when demand changes.
  • Pay according to the selected pricing model and usage.
  • The provider manages the physical infrastructure.
  • Applications and data are accessed remotely through a network.

Figure: Problems of traditional computing and how cloud solves them

2.2 Benefits of Cloud Computing

YELLOWImportant for 5 and 15 marks

Figure: Ten benefits of cloud computing

1. Cost savings

Reduces the need to buy expensive servers, storage and networking equipment. Rent resources and pay by usage instead of a large initial investment.
Example: a startup rents a virtual server from AWS instead of buying a physical one.
Remember: cloud is not always free or cheaper. Poor resource management can also increase costs.

2. Scalability

The ability to increase or decrease computing resources according to requirements.
Example: during a festival sale an e-commerce site adds server capacity, then reduces it after the sale.

3. Flexibility

The ability to use and adjust resources according to changing requirements, without buying new physical infrastructure each time.
Example: a software company uses extra cloud storage or computing power for a new project.

4. High accessibility

Services can be accessed from different locations and devices through the Internet.
Example: upload a document to Google Drive from your phone, open it on your laptop.

5. Reliability

Providers generally use backup systems, redundant infrastructure and data replication to reduce the impact of hardware failures.
Example: if one storage device fails, a properly configured system retrieves the data from another copy.
Important: reliability depends on the provider’s design and the customer’s configuration. Cloud does not guarantee zero downtime.

6. Faster deployment and speed

Cloud resources can be created much faster than buying and installing hardware.
Example: a developer creates a virtual machine within minutes.

7. Easy collaboration

Multiple users can work on shared files and applications from different locations.
Example: several students edit the same Google Docs document.

8. Data backup and disaster recovery

Backup and recovery services help restore information if hardware is damaged or data is deleted.
Example: a company keeps cloud backups of its business database to recover after a server failure.

9. Automatic updates and reduced maintenance

Providers handle many infrastructure tasks such as hardware maintenance and certain software updates, reducing the IT team’s workload.
Example: a managed cloud database. Customers may still update their own applications and manage their data.

10. Global reach

Providers have infrastructure in multiple regions, so applications can be deployed closer to users, improving accessibility and reducing delay.
Example: an Indian company deploys its application in an AWS region closer to European customers.

Topic 4. Cloud and Virtualization

YELLOWYELLOW priority: related to previous-paper questions, understand properly

WHY IMPORTANT?

Virtualization is one of the technologies that makes cloud computing possible. It helps providers use physical hardware efficiently and give virtual resources to multiple users.

Covered here: meaning of virtualization, meaning of cloud, relationship between them, how virtualization works, role of the hypervisor, difference, advantages and limitations.

4.1 What is Virtualization?

Virtualization is a technology that creates virtual versions of computing resources, such as computers, servers, operating systems, storage and networks, using software.

It lets multiple virtual environments run on a single physical machine. Instead of buying separate computers for different tasks, one powerful computer creates multiple virtual computers.

Example

A company has one powerful server and wants to run Application A (Linux), Application B (Windows Server) and Application C (another Linux environment). Without virtualization it may need three physical servers. With virtualization it creates three virtual machines on one server. Each VM behaves like an independent computer with its own operating system and applications.

Figure: Virtualization: three VMs on one physical server

4.2 What is a Virtual Machine (VM)?

A Virtual Machine is a software-based computer that behaves like a physical computer. It has virtual CPU, RAM, storage, network interface and an operating system.

Example: on a Windows laptop you create a VM to run Ubuntu Linux.

  • Host machine = the actual physical computer.
  • Guest machine = the virtual computer running on the host.

Figure: Host machine and guest virtual machine

4.3 What is a Hypervisor?

A Hypervisor is software (or a software layer supported by hardware) that creates and manages virtual machines. It allocates physical CPU, RAM and storage to different VMs.

Example: a server with 16 CPU cores, 64 GB RAM and 1 TB storage. The hypervisor allocates different portions to multiple VMs, manages the allocation and keeps VMs isolated from one another.

Type 1 and Type 2 hypervisors are studied in detail in Unit V.
Examples: VMware ESXi, Microsoft Hyper-V, Oracle VirtualBox.

Figure: Hypervisor dividing server resources among VMs

4.4 What is Cloud Computing?

Cloud Computing provides computing resources such as servers, storage, databases and networking over the Internet whenever users need them. Instead of buying and maintaining physical infrastructure, users access resources provided by a cloud service provider.
Example: Amazon EC2 lets users create and use virtual servers through AWS.

4.5 Relationship between Cloud Computing and Virtualization

REDMost important part of this topic

They are related but not the same. Virtualization is a technology, whereas cloud computing is a way of delivering computing resources as services.

Virtualization creates multiple virtual resources from physical hardware. Cloud computing uses virtualization, resource pooling, automation and network access to deliver those resources on demand.

How are they connected? (AWS example)

  1. AWS has physical servers in its data centres.
  2. Virtualization divides their resources into virtual computing environments.
  3. The cloud platform manages and allocates these resources.
  4. Users request virtual servers when required.
  5. Users access them through the Internet and pay according to the pricing model.

Figure: How virtualization supports cloud computing

4.7 Benefits of Virtualization

  1. Better hardware utilization: multiple VMs share one physical server.
  2. Cost reduction: fewer physical servers needed.
  3. Isolation: each VM operates in a separate environment.
  4. Flexibility: different operating systems on the same machine.
  5. Easy management: VMs created, configured and managed through software.
  6. Scalability: virtual resources adjusted within available hardware capacity.
  7. Testing and development: test applications on different operating systems without extra computers.

Figure: Benefits of virtualization

4.8 Limitations of Virtualization

  • Performance overhead: VMs may be slower than running directly on hardware.
  • Resource competition: VMs may compete for CPU, RAM and storage.
  • Management complexity: managing many VMs can become complicated.
  • Host failure: if the physical host fails, its VMs may become unavailable unless recovery arrangements exist.
  • Security risks: a hypervisor vulnerability can potentially affect multiple VMs.

Topic 5. Cloud Services Requirements

BLACKBLACK priority: short notes, one-time reading

WHY STUDY THIS TOPIC?

Before choosing a cloud service, an organization must identify what it expects from it. A banking application, for example, needs strong security, high availability and reliable performance. These expectations are the Cloud Services Requirements.

5.1 Meaning

Cloud Services Requirements are the technical and operational conditions a cloud service must satisfy to meet the needs of its users or organizations. In simple words: what a cloud service must provide to work properly, securely and reliably.

5.2 Major requirements

1. Security

Protect data and applications from unauthorized access, theft and cyberattacks.
Example: a cloud database uses authentication and encryption to protect customer information.

2. Availability

The service should be accessible whenever users need it.
Example: an online banking application remains accessible throughout the day.

3. Reliability

The service should work consistently and correctly without frequent failures.
Example: cloud storage stores and retrieves files without unexpected data loss.

4. Scalability

Resources should increase or decrease with changing workloads.
Example: an online shop handles extra visitors during festival sales.

5. Performance

Acceptable response time, processing speed and network performance.
Example: a cloud application responds without unnecessary delays.

6. Network connectivity

Reliable network connectivity so users can communicate with cloud servers and access applications.

7. Backup and disaster recovery

Support data backup and recovery so important information can be restored after failures or disasters.

8. Interoperability and portability

  • Interoperability: different systems and cloud services can communicate and work together.
  • Portability: data and applications can move between compatible environments with minimum difficulty.

Figure: Major requirements of cloud services

5.3 Service Level Agreement (SLA)

An SLA is an agreement between a cloud service provider and a customer that defines the expected service level. It may include:

  • Service availability.
  • Response time and performance.
  • Security responsibilities.
  • Support and maintenance.
  • Backup and recovery arrangements.
  • Compensation or service credits if agreed targets are not achieved.

Example: a provider promises a particular monthly availability percentage. An SLA helps both parties understand their responsibilities and expected service quality.

Topic 6. Cloud and Dynamic Infrastructure

BLACKBLACK priority: short notes, one-time reading

WHY STUDY THIS TOPIC?

Traditional IT infrastructure is often fixed: the organization buys servers and decides how many resources it needs. Cloud infrastructure is flexible: resources can be allocated, adjusted and released as requirements change. This dynamic management is the central idea of the topic.

6.1 Meaning of Dynamic Infrastructure

Dynamic Infrastructure is an IT infrastructure in which computing resources such as servers, storage and networks can be allocated, adjusted and released according to changing requirements.

In simple words: instead of keeping the same amount of resources all the time, an organization changes them whenever needed.

Example: a shopping website normally gets 1,000 visitors a day, but 50,000 during a festival sale. Cloud infrastructure provides extra servers for the increased traffic and releases them when demand falls.

6.2 What is Cloud Infrastructure?

The hardware and software resources required to provide cloud services. Main components:

  1. Servers: process requests and run applications.
  2. Storage: stores files, databases and other information.
  3. Networking: connects users, servers and cloud services.
  4. Virtualization: creates virtual resources from physical hardware.
  5. Management software: controls resource allocation, monitoring and provisioning.

Figure: Components of cloud infrastructure

6.3 How does Dynamic Infrastructure work?

  1. Monitor demand: the system monitors CPU, memory and network traffic.
  2. Allocate resources: additional resources are provided when required.
  3. Scale infrastructure: server capacity or storage is increased or decreased.
  4. Release resources: unnecessary resources are released when demand falls.

This process can be automated using cloud management tools.

Figure: Working of dynamic infrastructure

6.4 Role of virtualization and automation

  • Virtualization: separates computing resources from physical hardware and creates virtual machines or other virtual resources.
  • Automation: automatically provisions, configures and manages resources according to predefined requirements.

Together they help providers deliver resources quickly and efficiently.

Figure: Dynamic infrastructure: resources follow demand (example numbers)

6.5 Benefits of Dynamic Infrastructure

  1. Flexibility: resources change according to requirements.
  2. Scalability: supports increasing workloads.
  3. Better resource utilization: fewer idle resources.
  4. Cost efficiency: avoid paying for unused resources when pricing is usage-based.
  5. Faster deployment: new computing environments created quickly.
  6. Automation: less manual infrastructure management.

6.6 Exam-ready answer

Q. What is Cloud and Dynamic Infrastructure?
Dynamic Infrastructure is an IT infrastructure in which computing resources such as servers, storage and networks can be allocated, adjusted and released according to changing requirements. Cloud infrastructure consists of servers, storage, networking, virtualization and management software.

Dynamic infrastructure works through these steps:

  1. Monitoring resource requirements.
  2. Allocating resources according to demand.
  3. Increasing or decreasing computing capacity.
  4. Releasing unnecessary resources.

Virtualization and automation play important roles in managing it.
Example: an e-commerce website uses extra cloud servers during festival sales and reduces them when traffic decreases.
Thus, dynamic infrastructure makes cloud computing flexible, scalable and efficient.

Topic 7. Cloud Computing Characteristics

YELLOWYELLOW priority: moderate detail, important fundamentals

WHY IMPORTANT?

Cloud Computing has special features that distinguish it from traditional computing. They explain how resources are accessed, shared, increased or decreased, and billed. The most important exam point is the five essential characteristics defined by NIST (National Institute of Standards and Technology). Learn these five carefully.

7.1 Meaning

Cloud Computing Characteristics are the special features that describe how cloud services work and how they provide resources to users. In simple words, they explain what makes cloud computing different from traditional computing. According to NIST, cloud computing has five essential characteristics.

7.2 Five essential characteristics

REDImportant: learn all five

1. On-demand self-service

Users obtain computing resources such as servers and storage whenever needed, without contacting the provider’s staff.
Example: you create a virtual server on AWS yourself through its website.
Remember: the user requests the resource and the cloud platform provides it automatically.

Figure: On-demand self-service

2. Broad network access

Cloud services are available over a network and can be accessed through different devices using standard network mechanisms.
Example: Google Drive from a mobile phone, laptop, tablet or desktop.

Figure: Broad network access: one service, many devices

3. Resource pooling

The provider combines its computing resources (servers, storage, processing power, network resources) into a shared pool and provides them to multiple customers according to their requirements.
Example: one provider uses a large shared infrastructure to serve different companies.
Remember: multiple customers share a common pool, while their environments are logically separated.

Figure: Resource pooling: many customers share one pool

4. Rapid elasticity

Resources can be quickly increased or decreased according to changing demand.
Example: a shopping site normally has 1,000 visitors a day, 50,000 during a festival sale. The cloud adds resources for the extra traffic and reduces them later.
Remember: scale up = increase resources, scale down = decrease resources.

Figure: Rapid elasticity: scale up and scale down

5. Measured service

Resource usage is monitored, measured and reported by the provider. Customers can track consumption and are often charged according to use.
Example: if you use 100 GB of cloud storage, the provider measures it and calculates charges by its pricing model.
Remember: it works somewhat like an electricity meter.

Figure: Measured service

Figure: Five essential characteristics of cloud computing (NIST)
